# 한국 릴스 설득 가이드

버전: 2026-10-03. 한국어 고객의 생활 장면과 구매 이유를 연결하는 HIOB 제작 지침이다. 아래 시간·문장 구조는 실험 출발안이며 보편적인 최적 길이·매출·알고리즘 효과를 보장하지 않는다. 고객이 지정한 길이·메시지·숫자·표현을 먼저 보존한다. 한국어가 아닌 릴스에는 해당 언어의 실제 사례를 사용한다.

## 1. 본편과 소재를 먼저 구분한다

첫 기획에 목적(구매/문의/저장/공유), 타깃의 구체적인 상황, 본편 길이, 선택한 전개, 확인 가능한 제품 근거를 적는다. 고객이 42초를 요청하면 42초 본편으로 기획한다. 5–15초 생성 원본이나 짧은 시안은 내부 소재이며 본편 납품으로 표시하지 않는다. 길이 미지정의 설명·구매 설득형 한국 릴스는 아래 42초 안을 먼저 제안하고 선택 이유를 쓴다. 밈·상황극·브랜딩 등에 일괄 강제하지 않는다.

이미지 3장·인물·소품·배경 카드는 기획과 생성 참조다. 사진의 줌·패닝·전환은 사용 동작을 보여 주는 동영상이 아니다. 핵심 장면에는 시작 상태→실제 행동→끝 상태를 설계한다. 정지 리뷰·사양·시험 자료 화면은 출처와 읽을 시간이 있는 증거 화면으로 쓸 수 있다. AI 생성 사용 장면은 연출이며 실제 효능 실험을 대신하지 않는다.

## 2. 먼저 전개 하나를 선택한다

| 전개 | 맞는 자료·상황 | 문장 연결 |
|---|---|---|
| 권위 인용형 | 제품 문제와 관련된 유명인·전문가의 확인된 발언 | 발언/선택 기준 → 내 생활 문제 → 제품 차이·원리 → 제품 자체의 증거 → 조건·CTA |
| 문제 공감형 | 고객의 불편과 기존 대처가 구체적 | 불편 행동 → 반복되는 실패/손실 → 해결 원리·사용 → 증거 → CTA |
| 시연·비교형 | 실제 사용·동일 조건 비교 자료가 있음 | 관찰할 차이 → 조건 → 실제 과정 → 결과·한계 → 적합 대상·CTA |
| 후기형 | 원자료가 있는 고객 경험 | 사용 계기 → 망설임 → 실제 사용 → 달라진 점과 한계 → CTA |
| 상황극형 | 관계·오해·반전이 제품과 연결됨 | 사건 → 상대 반응 → 예상과 다른 행동 → 제품의 역할 → 회수 |

여러 전개의 제목을 모두 붙이지 않는다. 주 전개 하나에 필요한 보조 장치를 선택한다. 사회적 증거는 마지막에만 쓰는 항목이 아니다. 실제 추천이나 권위 발언을 첫 화면에 놓을 수 있고, 본문에서는 우리 제품의 구매 이유를 따로 설명한다.

## 3. 유명인의 말로 시작하는 법

다음 네 가지를 구분한다.

- **일반 발언/권위 인용:** 확인된 문제 인식·습관·선택 기준. 우리 제품 사용·추천의 증거가 아니다.
- **실제 제품 추천:** 해당 제품을 실제 사용·추천한 원자료가 있는 경우. 다른 제품/과거 모델의 발언을 바꾸지 않는다.
- **고객의 사회적 증거:** 출처 있는 구매 후기·사용 경험·집계 기준이 있는 리뷰. 합성 인물을 실제 고객처럼 제시하지 않는다.
- **제품 실증:** 사양·작동 구조·시연·조건이 확인된 시험 자료. 인기나 유명인의 권위로 대체하지 않는다.

인용 카드에는 `인물/직함 | 원본 URL·발언일 | 원문 | 직접 인용/요약 | 원래 맥락 | 실제 제품 추천 여부 | 우리 문제와 연결되는 이유 | 확인 상태`를 쓴다. 원본을 확인하지 못하면 미확인으로 남기고 확정 대본에서 제외한다. 검색 명언 카드만 보고 발언을 확정하지 않는다. 요약문에는 원문인 것처럼 따옴표를 붙이지 않는다.

도입 작성식은 `[이름/직함]의 [짧고 확인된 말] → 그 말이 고객의 [구체적 상황]에서 뜻하는 것 → 우리 제품이 그 기준에 맞는 [확인된 이유]`다. 일반 발언을 제품 옆에 배치해 추천처럼 읽히게 하지 않는다. 유명인의 얼굴·목소리·추천 발언을 합성해서 근거를 만들지 않는다. 인용의 확인과 원본 영상·음성의 사용 조건 확인은 별개다.

**약한 연결:** “유명한 사람이 꾸준함이 중요하대요. 그러니 우리 제품을 사세요.”
**고치는 질문:** 그 말이 어떤 고객 문제를 설명하는가? 우리 제품의 어떤 구조가 그 문제를 다루는가? 이를 보여 줄 근거가 있는가? 연결이 없으면 그 인용을 빼고 문제에서 바로 시작한다.

## 4. 우리 제품이 왜 좋은지 설명하는 법

핵심 구매 이유 한 가지를 다음 여섯 단계로 쓴다.

1. 고객은 **언제, 어떤 행동에서** 막히는가?
2. 지금 대처는 **왜 그 상황에서 부족한가**? 고객을 탓하거나 경쟁 제품 전체를 비하하지 않는다.
3. 우리 제품의 **확인된 구조·사양·사용 방식 차이**는 무엇인가?
4. 그 차이는 **어떻게 작동하는가**? 손·제품·대상 사이의 과정을 설명한다.
5. 고객은 **무엇을 덜 하거나 더 쉽게 할 수 있는가**, 무엇으로 확인하는가?
6. **어떤 사람/조건에 맞는가**, 구매 전 무엇을 확인해야 하는가?

문장 틀: `[기존 상황]에서는 [불편]이 생겨요. 이 제품은 [확인된 특징]으로 [작동 방식]을 사용할 수 있어요. 그래서 [근거 범위 안의 이점]이 있습니다. [실제 자료/동작]로 확인하고 [선택 조건]을 살펴보세요.` 그대로 낭독하지 말고 브랜드 말투로 고친다.

“프리미엄·첨단·특허·인생템”은 구매 이유의 설명이 아니다. 특허가 있어도 그 자체로 효능·우월성이 입증된 것은 아니다. 사양·작동 원리·고객 이점의 연결을 적는다. 소재의 일반적 성질만으로 완제품의 성능 수치를 만들지 않는다. 장점 세 개를 빠르게 나열하기보다 핵심 차이 하나를 이해시키고 필요할 때 보조 장점을 붙인다.

## 5. 42초 기본 배분과 증거의 위치

| 구간 | 역할 | 작성·화면 규칙 |
|---|---|---|
| 0–3초 | 후킹 | 확인된 인용, 불편 행동, 실제 관찰 결과 중 하나. 이름 소개로 시간을 소비하지 않음 |
| 3–12초 | 공감 9초 | 구체적 생활 장면·실패한 대처·손실. 같은 문제를 반복하지 않고 해결 단서를 미리 보여 줄 수 있음 |
| 12–27초 | 설명 15초 | 원인만 설명하지 않음. 제품의 차이→작동 원리→사용 동작→이점 |
| 27–37초 | 증거 10초 | 확인된 후기 또는 제품 자료·시연. 가장 큰 구매 질문 하나와 조건·한계 |
| 37–42초 | CTA 5초 | 첫 질문/기준 회수→행동 하나→실제 도착점. 5초 정지 카드로 채우지 않음 |

이는 권장 설계표다. 증거를 앞으로 이동하거나 실제 발화에 맞게 경계를 조정할 수 있다. 고객이 지정한 길이와 다른 안을 선택하면 이유와 변경 내용을 명시한다. 3초 후킹+추가 9초 공감은 12초까지이고, 기존 “9초 안에 계속 볼 이유”와 같은 시간 단위가 아니다. 해결 단서는 9초 이전에도 보여 준다. 짧은 축약본은 별도 산출물로 이름 붙인다.

증거가 없으면 사회적 증거를 만들지 않는다. 증거 유형을 제품 사양/실제 시연으로 바꾸거나 미확보를 표시한다. 원자료가 있는 후기라도 결과를 모든 고객에게 보장하지 않는다. 시험 조건·표본·비교 기준을 생략해 의미를 바꾸지 않는다.

## 6. 한국어 말맛·자막·소리

고객이 실제로 할 법한 말로 상황을 연다. “불편함을 느끼시는 소비자”보다 “방금 쓴 펜, 또 찾고 있죠?”처럼 행동이 보이는 문장을 쓴다. “근데”, “그래서”, “막상 써보면”은 실제 반전·원인·경험이 있을 때만 쓴다. 모든 문장을 “대박·미쳤다·모르면 손해”로 시작하지 않는다. 없는 체험을 “제가 써봤는데”로 꾸미지 않는다.

발화는 의미가 이어지는 짧은 구어체로 쓰고 낭독해 어색한 조사를 고친다. 자막은 의미 구절로 나누고, 강조 문구와 실제 대사 자막이 서로 다른 약속을 하지 않게 한다. 고정 글자수·일괄 배속으로 시간을 맞추지 않는다. 선택한 음성의 실제 길이·쉼·끝음절로 보정한다.

나레이션은 사용 과정 위에 이어질 수 있다. 인물이 말하는 컷은 원문 대사·화자·입 움직임을 확인한다. 반응·상황 전환에 효과음을 쓰되 근거 없는 효능을 성공 효과음으로 과장하지 않는다. 상황극의 침묵·표정·상대 반응은 의도한 시간으로 남길 수 있다.

## 7. 기획표와 현재 MCP 대응

MD 기획표: `구간 | 한국어 대사 | 설득 역할 | 주장 유형·출처 | 제품과 연결되는 이유 | 시작→행동→끝 | 자막 | 소리 | 참조 이미지 | 동영상 원본·in/out | 구매 질문 | 확인 상태`.

현재 `plan.durationSec`와 연속된 `beats.start/end`에 본편 시간을 옮긴다. 제품 주장은 `claims` 원자료와 `beat.claimIds`로 연결한다. 일반 인용을 제품 추천 claim으로 만들지 않는다. 실제 동작은 `direction.assets.action/productAction`, 원본 길이와 편집은 `assets.duration` 및 `cuts.sourceInSec/start/end`에 대응한다. 기획표의 별도 열을 지원되지 않는 API 필드로 보내지 않는다. 스키마·문장 존재 검사는 내용의 진실·재미·사람의 승인을 판정하지 않는다.

검수에서 초안·실제 음원·조립본·최종 MP4의 총길이와 다섯 설득 역할을 비교한다. 요청보다 짧으면 어느 구간이 빠졌는지 설명한다. 이미지 줌을 실제 사용 동작으로, 프레임 표본을 전체 영상 관찰로 기록하지 않는다. 최종 동영상과 소리를 실제로 보고 들은 범위를 표시한다.

## 8. 초안을 다시 써야 하는 경우

- 제품명을 바꿔도 같은 문장이 성립함 → 확인된 구조·사용법·조건을 추가한다.
- 좋은 이유가 형용사뿐임 → 원리와 보여 줄 행동·근거를 적는다.
- 유명인 발언이 제품 추천처럼 읽힘 → 문제 기준과 제품 자체 증거를 분리해 다시 쓴다.
- 첫 약속을 끝까지 확인시켜 주지 않음 → 증거 또는 약속을 수정한다.
- 정지 이미지 확대가 핵심 동작을 대신함 → 이미지 시안으로 표시하고 동영상 소재를 준비한다.
- 증거가 없는데 후기·수치를 넣음 → 해당 문장을 제거하거나 미확보 자료로 남긴다.
- 42초 본편 요청이 생성 원본 한 개로 끝남 → 본편의 누락된 설득 구간을 다시 계획한다.
