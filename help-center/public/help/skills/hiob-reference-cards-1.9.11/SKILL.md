# 인물·제품·소품 카드 만들기

카드는 장면마다 무엇을 유지할지 정하는 계약이다. 카드 이름만 적는 것으로 모델에 이미지가 전달되지는 않는다. 기존 카드가 있으면 새로 만들지 말고 원본과 수정 요청을 먼저 확인한다.

1. 역할을 정한다: `character` 인물 정체성, `product` 판매 제품의 사실, `prop` 반복 소품, `material` 표면/변형 규칙. 인물 없는 광고에 인물을 만들지 않는다. 카드 수는 실제 재사용/보존 필요에 맞춘다.
2. 실제 제공/생성 이미지를 열어 관찰한다. 인물은 중립적인 표정·단순 배경·균일한 빛으로 얼굴과 실루엣을 판단하기 쉽게 만든다. 제품은 실제 모양·라벨·색·부속품을 확인할 각도를 선택한다. 분위기와 조명은 스타일프레임에서 정한다.
3. 고유 ID, 역할, 이미지의 실제 위치/자산 ID, 제공자/생성 출처, 직접 본 범위, 유지할 특징, 바꿔도 되는 특징, 고객 선택 여부를 적는다. [카드 양식](references/card-template.md)을 필요할 때 읽는다.
4. 환상 재료는 표면의 결·두께·불투명도와 힘을 받았을 때의 행동을 정한다. 제품 성능을 암시하는 표현은 입증된 사실과 예술적 은유를 구분한다.
5. 카드와 실제 입력의 연결을 확인한다. 텍스트 ID, 파일명, URL, 파일 해시는 서로 다르다. 파일이 없으면 해시나 assetId를 만들어 채우지 않는다. 텍스트 설계만 있으면 이미지 미생성, 미리보기만 있으면 원본 미확보로 남긴다.

## HIOB에서 실행할 때

`capability_list(owner="parzifal")`와 `capability_list(owner="artemis")`에서 정체성·제품 증거 책임과 현재 고객 경로를 찾는다. 카드·장면의 실제 원본을 저장·동기화한 뒤 `capability_prepare`로 서버 준비 상태를 확인한다. 서버가 현재 파일·해시·revision을 검증하며 로컬 Python으로 영수증을 만들지 않는다. 인물 없는 요청과 기존 카드 재사용은 서버가 입력을 평가하며 카드 수나 유료 이미지 생성 횟수를 일률 강제하지 않는다. 이미지 ID/프롬프트만으로 실제 참조를 대신하지 않는다.

`project_context`로 기존 자산/선택/권한과 전체 제작 지침을 읽는다. 실제 이미지 파일을 저장할 때 `asset_save` 또는 `asset_import`의 **현재 입력 스키마**를 사용한다. 사용자 동의를 나타내는 `userConfirmed`를 AI 판단으로 true로 만들지 않는다. `image_select`는 실제 장면 후보를 선택하는 작업이며 카드 목록을 자동 선택/합성하는 도구가 아니다.

참조 개수/종류는 `model_catalog`에서 확인한다. 인물·제품·재질 카드가 셋 있다고 동영상 생성이 세 이미지를 받는다고 가정하지 않는다. 단일 참조 입력이라면 현재 이용 가능한 이미지 제작/합성 경로에서 고객이 선택한 장면 이미지로 통합한 뒤 그 실제 파일을 사용하거나, 실행 미지원 상태를 표시한다. 이미지 조합 기능을 발명하지 않는다. 카드를 등록했다고 동의·원본 정합성·광고 권리·최종 품질이 모두 확인된 것은 아니다.

산출물은 카드 목록과 연결된 미리보기다. 표시할 수 없으면 이유와 실제 파일 링크를 제공한다. ‘이미지 카드 완료’라고 텍스트만 전달하지 않는다.

## 구체적인 인물 카드와 계정 보관함 재사용

인물 카드에는 이름·광고 역할, 나이대·성격·설정, 얼굴 비율·눈/코/입·피부 톤·체형·헤어·고유 특징, 의상 색/소재·액세서리·소품, 표정·시선·몸짓, 말투·속도·음색·선택한 voiceId/설정, 고정할 특징, 바꿔도 되는 특징을 구체적으로 적는다. ‘멋진 여성’, ‘전문가 느낌’ 같은 추상어만으로 정체성을 정하지 않는다. 실제 원본에 보이지 않는 특징은 확인되지 않은 설정으로 표시한다. 인물 없는 광고에는 인물 카드를 강제하지 않는다.

저장 위치는 HIOB 계정 보관함 `/characters`다. `character_vault`로 주소를 확인한다. 사용자가 확인한 실제 PNG/JPEG 원본, 출처, 사용 승인 문구·제한과 위 설정을 한 카드 버전으로 저장한다. 원본 없이 텍스트 설계만 있는 카드는 준비 중으로 표시한다. 이미 저장한 카드부터 검색·시각 확인하고 얼굴 참조를 다시 생성하지 않는다.

계정 보관함과 프로젝트의 역할을 구분한다. 보관함은 로그인한 계정 소유이며 브랜드/프로젝트의 임시 저장소가 아니다. 새 프로젝트마다 사용자가 해당 카드 버전을 명시적으로 연결한다. 연결된 프로젝트의 협업자는 선택한 카드만 참조할 수 있다. 프로젝트 전용 MCP 권한은 계정 전체 목록을 읽는 권한이 아니다. 브라우저에서 선택·연결한 뒤 `character_list(projectId)` → `character_import(projectId,cardId,expectedSha256)`로 원본과 상세 설정을 가져온다. 반환된 file·sha256과 카드 버전 ID를 기획서에 기록하고 `direction_save`의 실제 referenceFile로 연결한 뒤 `project_sync`한다. 모델의 실제 참조 입력 지원을 확인한다.

베스트 프랙티스: 고정 정체성과 광고별 역할·감정·조명·포즈를 분리한다. 원본은 덮어쓰지 않고 정보나 외형을 바꿀 때 parentId로 연결된 새 버전을 저장한다. 기존 프로젝트는 선택한 버전을 유지한다. 보관함에서 숨겨도 이미 연결한 프로젝트의 원본 참조는 유지되므로 권리 철회가 필요하면 연결된 프로젝트도 별도로 확인한다. 여러 브랜드에 재사용하기 전에 카드에 적힌 사용 범위·동의·기간을 확인한다. 실존 인물의 초상·목소리 사용 승인을 자동으로 인정하지 않는다. 실패한 업로드는 같은 요청 ID·같은 원본으로 재개한다.

카드 가져오기는 원본 복사·설정 재사용이며 유료 생성·선택 자동 승인·완성 영상 품질 인증이 아니다. 새로운 동작의 영상이나 새 문장의 TTS가 필요하면 기존 정체성/목소리 설정을 재사용하되 새 제작 견적과 허용 범위를 따른다. 카드 이미지가 같아도 새 장면의 얼굴·의상·말투 일치는 실제 결과를 보고 확인한다.

## 2026-10-04 필수 13구도 준비

새 영상 제작은 Parzifal의 `reference_prepare`를 실제 실행해야 한다. 화면에 등장하는 인물마다 한 카드 버전과 서로 다른 실제 PNG/JPEG 13장을 준비한다: face_front, face_left_45, face_right_45, head_left_profile, head_right_profile, head_back, head_left_rear_45, head_right_rear_45, body_front, body_back, medium_high_left, medium_low_right, hands_props. 얼굴·머리·체형·복장·액세서리·소지품 고정값을 연결한다. 한 시트에 13구도를 만든 경우 직접 확인한 각각의 패널을 별도 파일로 추출하고 원본 시트와 좌표도 보존한다. 같은 정면 사진을 13번 선언하지 않는다. 실제 모델 입력에 맞춘 장면 첫 프레임을 별도로 만들어 카드를 반영한다. 13장 전부를 단일 참조 모델에 전달한다고 주장하지 않는다.

제품은 Artemis로 관찰한 브랜드 실물 원본과 보존값을 준비한다. 생성된 제품 라벨을 실물 원본으로 기록하지 않는다. 준비 결과는 draft_prepared이며 승인·초상권·성능·유료 실행 권한을 부여하지 않는다. 기존 승인 스냅샷 노드는 계속 승인된 master만 받는다. 인물이 없는 장면은 인물을 추가하지 않고 noCharacterReason을 기록한다. 준비·조회는 계속할 수 있지만 새 영상 견적/접수는 준비 계약이 없거나 변경되면 중단한다.


## 어느 호스트에서나 같은 시각 준비
인물 마스터카드(큰 얼굴·앞뒤 전신·프로필·표정·옆/뒤통수·의상/소지품), 동일 인물 13구도와 6표정, 실제 제품 사진, 세계관(팔레트·빛·질감·모티프·연속성), 대본 의미로 회수되는 시각적 전환 컷을 준비한다. 컷별 시작 프레임과 렌즈·각도·이동의 시작/행동/끝/이유를 고정한다. `creative_skills(skill=hiob-reference-cards,resource=references/wow-master-card.md)`를 읽는다. `plan_save → direction_save → reference_prepare → storyboard_compile`로 실제 파일과 Parzifal·Artemis 실행 기록을 결박하며 신규 영상 견적/접수 전에 검증한다. 이미지 생성 성공·시각적 은유는 제품 효능 증거가 아니다.

제품이 없는 창작은 제품 사진이나 근거를 꾸며 채우지 않는다. products:[]와 noProductReason을 작성하고 기획의 claims:[]를 명시한다. 서버는 실제 저장된 기획을 확인하고 Artemis의 빈 초안 준비 결과도 실행 기록으로 보존한다. 이 사유는 제품·사회적 증거가 있는 광고의 근거 요구를 해제하지 않는다.

## 인물이 등장하는 모든 컷의 육도 연기 (2026-10-08)

**모든 인물 컷은 육도 감정이 표정·시선·자세·손·움직임에 보여야 한다. 이미지의 감정이 영상·립싱크·최종 편집에서 사라지면 통과가 아니다.** 호스트가 저장된 `direction.assets[].realm/expression/action`을 읽어 장면의 시작 → 주요 행동 → 반응으로 연결한다. 지옥은 압박과 긴장, 축생은 두려움과 방어, 아수라는 경쟁과 좌절, 인간은 분투와 의심, 아귀는 갈망과 기대, 천상은 얻어낸 안도다. 한 컷에 한 감정을 출발점으로 삼고 기존 승인 연출을 우선한다.

손 전용 컷은 손의 긴장·속도·주저함/확신으로 표현한다. 인물 없는 컷에 사람을 추가하지 않는다. Seedance의 CHARACTER 150단어와 얼굴 없는 참조 규칙을 유지하고 연기는 SCENE AND ACTION에 둔다. 같은 나레이터·승인 전문·목소리·타이밍을 보존하며 감정 보완을 이유로 기존 음원을 자동 재합성하지 않는다.

`storyboard_compile`의 실제 prompt에 의도가 전달됐는지 확인한다. 이후 원본 영상과 립싱크 결과를 실제로 보고 `material_review.sceneChecks`의 `person_body.note`에 타임코드·의도·관측된 연기·손상 여부를 기록한다. 최종 MP4에서도 같은 컷을 다시 본다. 프롬프트 전달, 실제 표현, 립싱크 후 보존은 별도 판정이다. 누락 시 원본 연출과 해당 소재를 읽어 보완하고 기존 성공 소재를 재사용한다. 관찰 없이 pass를 만들거나 무표정 포트레이트로 대체하지 않는다. 막힌 경우 `error_record`에 같은 작업/incident ID와 복구 결과를 남긴다.
