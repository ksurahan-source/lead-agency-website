# HIOB 영상 제작

사용자의 창작 방향·자료·기존 선택이 기준이다. 로컬 AI는 이해·기획·편집 판단을 맡고 Studio는 권한·버전·비용을 보관한다. 필요한 무거운 처리는 기존 서버·행성이 수행하며 최종 MP4는 Hephaestus → Remotion AWS Lambda가 만든다.

## 시작과 재개

설치된 도구 목록을 확인하고 기존 프로젝트의 project_context를 읽는다. workflow·productionGuide·판단 문서에서 현재 대사·선택 자산·음원·편집을 복원한다. 리소스를 열 수 없으면 [제작 절차](references/production-workflow.md)를 읽고 실제 도구 스키마를 확인한다. release_check는 공개/실행 버전, production_check와 render_status는 현재 서버·승인·한도를 확인한다. runtime_check는 클라이언트 조건만 확인한다.

같은 기기의 새 세션·호환 업데이트는 connection_resume으로 유효한 승인을 재사용한다. 같은 승인 범위 안에서는 단계별 새 동의를 요구하지 않는다. 실제 만료·철회·새 범위만 구분해 안내한다. 고객 승인 없이 권한·예산을 확대하지 않고 서버 오류를 재승인으로 해결하지 않는다. 고객에게 최종 렌더 엔진이나 컨테이너 설치를 요구하지 않는다.

## 목소리 선택

narrationSource에 recording·typecast·mixed를 보존한다. 녹음이 있으면 원본을 보존하고 실제 대사·길이·쉼을 먼저 확인해 장면과 구절 자막을 설계한다. audio_set은 직접 녹음도 연결하며 Typecast 합성 권한·비용이 필요하지 않다. 영상 생성과 최종 렌더 비용은 별도다. 녹음 모드에서는 합성 후보로 대체하지 않는다. 혼합은 요청한 문장만 AI 음성으로 보완한다.

전사 결과와 자막 시각은 실제 발화에 대조한다. 없는 단어·시각을 추측하지 않고 불확실한 부분은 미검증으로 남긴다. 원본을 덮어쓰거나 발화를 억지로 자르지 않는다. 호스트가 청취할 수 없다면 들었다고 보고하지 않는다.

## 창작과 제작

제품 원문의 확인한 주장·조건을 보존한다. 훅의 약속은 9초 이내에 완성하고 CTA가 이를 회수하게 한다. 나레이터·주인공·증인은 역할이며 고정 출연자 수가 아니다. 육도는 감정·행동 설계에 쓰고 영상 모델에 설명문으로 보내지 않는다. 승인된 인물·제품 참조로 원본 소재를 만들고 필요한 컷에 재사용한다. 24컷은 24번 유료 생성이 아니다.

원본 소재는 material_inspect의 실제 프레임을 보고 material_review로 기록한다. 생성 원본을 완성 광고로 전달하지 않는다. 선택 음원·큰 구절 자막·제목·효과음을 edit_assemble로 조립한다. 가로/세로 모두 고정 서버 편집 계약을 사용한다. 기존 수동 코드는 체크포인트에 보존하고 연출을 확인한 뒤 명시적으로 전환한다.

project_sync → render_quote → 승인 범위 안의 render_start(final, quoteId) → render_status → render_download로 진행한다. 애매한 응답은 같은 작업 ID로 조회하며 새 유료 접수나 로컬 final로 대신하지 않는다. 검증된 MP4를 실제로 보고 들어 제품·발화·자막·호흡을 확인하고 필요한 구간만 수정한다. review_save는 실제 검수한 범위만 기록한다. project_publish와 독립 세션 복원 결과도 확인한다.

## 결과 보고

소스 검사, 배포, 실제 서버 영상, 실제 고객 환경, 창작 검수를 각각 구분한다. 스킬이나 테스트 통과만으로 영상 품질·광고 성과를 보장하지 않는다. MCP 0.9.0 후보 / 스킬 1.2.0: 공개 여부와 실제 사용 가능 범위는 현재 서버 응답으로 확인한다. 미디어 검사 서버 연결이 준비되지 않았다면 그 부분을 완료로 소개하지 않는다.
