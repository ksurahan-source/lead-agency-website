## 고객 선택을 기본 허용하는 제작 정책 (2026-10-09)

한 나레이터는 기본 권장이다. 고객이 2인 대화와 MiniMax 순정 음성을 선택하면 그 선택으로 진행한다. 대본 전문은 하나로 유지하고 대사별 `beat.speakerId`를 `direction.speakers.castId`와 연결한다. `narratorScript.speakerId`는 생략된 beat의 기본 화자이며 모든 화자를 한 사람으로 합치는 명령이 아니다. native 경로에 Typecast voiceId·한 얼굴·Kling 후처리를 요구하지 않는다. 서로 다른 대사와 화자, 화면의 청자를 구분하고 실제 두 목소리·입모양·얼굴·연기를 검수한다.

기획·자료 준비·저장·조회·독립 작업은 기본 허용한다. 실제 권한 없음/비용 승인 범위 초과, 원문·타이밍·선택 화자 무단 변경, 파일/참조 무결성 불일치, 해당 제공사 단계의 확인된 입력 제한, 중복 유료 접수, 관찰 없는 품질 합격을 금지한다. 단일 얼굴 원본·5초·Typecast 요구는 현재 Kling 립싱크 경로의 제약이며 MiniMax 순정 2인 생성에 전역 적용하지 않는다. 복수 화자 전체 혼합 음원을 단일 화자 클로닝에 제출하지 않는다. Seedance 입력 참조 얼굴 제외·CHARACTER 150단어는 유지한다. 기존 성공 자료와 작업·원문을 일괄 무효화하지 않는다. 오류 코드는 정확한 사건 검색용으로 유지하고 호스트가 같은 ID로 구체적인 원인/해결을 처리한다.


# 육도를 실제 사건과 연기로

먼저 `project_context`의 승인 realm/expression/action, 인물·소품·브랜드·배경·카메라, speechMode, 원본·성공 작업·목소리·타이밍을 읽는다. 감정을 새로 배분하거나 기존 승인 인물을 자동 대체하지 않는다.

## 한 컷의 연기

`references/realm-beats.md`를 읽고 승인 행동을 아래 구조로 풀어 **연출 후보**를 반환한다. 그 후보가 승인 밖의 새 행동이면 바로 실행하지 않는다.

1. 외적 목표: 인물이 지금 해결하려는 구체적인 고객 상황.
2. 내적 억제: 의심·두려움·갈망 등이 행동을 어떻게 지연/긴장시키는지.
3. 사건: 제품/상황의 실제 변화가 반응을 유발하는 순간.
4. 전환: 준비→행동→반응의 시선·표정·자세·손·호흡·말 변화. 단순 blink/nod를 모든 컷에 반복하지 않는다.
5. 잔류: 얻어낸 감정과 소품/몸의 끝 상태. 다음 컷의 시작 상태와 연결한다.

새로운 목표/beat는 기획 문서이며 현재 도구 입력 필드를 발명하지 않는다. `direction_save`의 현재 schema에서 기존 realm/expression/action, continuity.stateBefore/stateAfter와 승인 카메라에만 결박한다. 기존 승인 범위를 넘어선 전환은 별도 후보로 남긴다. hands_only에서는 손·소품·힘·속도·전후 상태로 감정을 보여주고 얼굴은 화면/반사까지 나오지 않게 한다.

## 참조와 음성

인물/몸·소품/브랜드·배경/사용 상태·카메라 네 검수와 13구도·6표정을 유지한다. 연속성을 감정 카드 1~2장으로 축약하지 않는다. 시작 프레임이 좋다는 이유로 영상 전체를 통과시키지 않는다.

현재 선택한 H3 / Seedance 2 / Seedance 2.5 × native / lipsync **6개 경로**를 유지한다. native의 원본 발화·얼굴을 강제 립싱크로 바꾸지 않는다. lipsync만 해당 경로의 지정 Typecast 승인 전문 구간과 지원되는 후처리를 사용한다. LOTUS-Q는 서현, 메타 가이드는 필재를 보존한다. 실제 음성 파일/구간 길이가 타이밍의 권위다. 한글을 세지 않는 외부 발화율 검수기를 한국어에 사용하지 않는다.

Seedance면 로컬 `hiob/docs/usage/SEEDANCE_CHARACTER_INPUT.md`와 현재 `model_catalog`를 먼저 읽는다. 가상 인물은 영어 공백 기준 **정확히 150단어 CHARACTER**로 묘사하고 나머지 블록은 별도로 둔다. 모든 실제 업로드 참조는 경로·SHA·소품/배경 역할·얼굴 없음 관찰을 기록한다. 포장·화면·포스터·유리/거울 반사·실사형 AI 얼굴도 검사한다. 미관찰/판단불가/얼굴 포함 파일은 제출하지 않고 얼굴 없는 대체 자료를 준비한다. 인물 카드/얼굴/firstFrame으로 우회하지 않는다. 출력 인물 얼굴은 허용된다. 없는 @image 번호를 만들지 않는다.

## 관찰 후 기록

`references/observation-and-recovery.md`에 따라 원본→선택한 후처리→최종의 실제 영상·음성을 관찰하고 현재 `emotion_review`/`emotion_review_save` 계약으로 기록한다. native에는 존재하지 않는 lipsync stage를 강제하지 않는다. 각 상태의 변화, 움직임 중 얼굴 동일성/선명도, 손/소품 접촉, 발화/입모양, 실제 시간 구간과 원본/결과 hash를 비교한다. 관찰하지 않았다면 unverified이며 실제 pass를 만들지 않는다.

실패는 실제 job/request/incident/correlation ID로 중앙 기록을 이어 읽고 지원되는 복구/대안을 사용한다. 성공 자산 전체를 새 연기 정책으로 무효화하지 않는다. 현재 미확인 유료 작업을 재제출하지 않는다. 이 스킬의 발견/배포는 실제 인물 연기가 좋아졌다는 증거가 아니다.
