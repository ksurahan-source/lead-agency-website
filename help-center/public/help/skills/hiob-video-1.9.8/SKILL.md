# HIOB 영상 제작

사용자의 창작 방향·자료·기존 선택이 기준이다. 로컬 AI는 이해·기획·편집 판단을 맡고 Studio는 권한·버전·비용을 보관한다. 필요한 무거운 처리는 기존 서버·행성이 수행하며 최종 MP4는 Hephaestus → Remotion AWS Lambda가 만든다.

## 시작과 재개

설치된 도구 목록을 확인하고 기존 프로젝트의 project_context를 읽는다. currentStep·referencePreparation 요약과 workflow·productionGuide·판단 문서에서 현재 대사·선택 자산·음원·편집을 복원한다. 리소스를 열 수 없으면 [제작 절차](references/production-workflow.md)를 읽고 실제 도구 스키마를 확인한다. release_check는 공개/실행 버전, production_check와 render_status는 현재 서버·승인·한도를 확인한다. runtime_check는 클라이언트 조건만 확인한다.

[기능 선택과 서버 준비](references/capability-access.md)를 읽는다. `capability_list()`는 12행성·47노드의 계약과 기존 고객 도구 경로를 안내한다. 연결한 뒤 `capability_list({projectId})`로 실제 프로젝트의 서버 상태를 확인한다. 서버가 허용한 17개 무과금 탐색은 `capability_execute`로 실행하며, 유료 제작·봉인·게시·실제 측정은 해당 전용 경로와 현재 권한을 따른다. 계약 수를 모든 유료 모델의 필수 호출 횟수로 해석하지 않는다.

현재 파일을 `project_sync`로 저장하고 `capability_prepare({projectId,action:"planning"})`로 12행성의 준비 책임과 부족 자료를 확인한다. 새 영상에는 실제 견적 `plan`과 action=generation, 화면 편집 렌더에는 현재 `inputSha`와 action=render를 사용한다. 반환한 준비 영수증을 견적의 `readinessReceiptId`에 연결할 수 있다. 서버는 저장된 입력·현재 revision·권한을 다시 검증한다. AI의 pass 문구나 임의 비해당 선언으로 필수 책임을 없애지 않는다.

같은 기기의 새 세션·호환 업데이트는 connection_resume으로 유효한 승인을 재사용한다. 같은 승인 범위 안에서는 단계별 새 동의를 요구하지 않는다. 실제 만료·철회·새 범위만 구분해 안내한다. 고객 승인 없이 권한·예산을 확대하지 않고 서버 오류를 재승인으로 해결하지 않는다. 고객에게 최종 렌더 엔진이나 컨테이너 설치를 요구하지 않는다.

## 목소리 선택

narrationSource에 recording·typecast·mixed를 보존한다. 녹음이 있으면 원본을 보존하고 실제 대사·길이·쉼을 먼저 확인해 장면과 구절 자막을 설계한다. audio_set은 직접 녹음도 연결하며 Typecast 합성 권한·비용이 필요하지 않다. 영상 생성과 최종 렌더 비용은 별도다. 녹음 모드에서는 합성 후보로 대체하지 않는다. 혼합은 요청한 문장만 AI 음성으로 보완한다.

연결된 프로젝트는 project_sync로 녹음부터 저장한 뒤 audio_inspect → audio_inspection_status로 같은 작업의 길이·음량·쉼을 확인한다. 초기 저장에 완성 대본이나 Reel.tsx는 필요하지 않다. 이 검사는 선택한 Typecast 후보·음악·효과음에도 필요하며 done 결과를 확인한 뒤 audio_set으로 연결한다. 검사는 원본 해시와 트림·속도·볼륨에 묶이므로 변경 후 다시 확인하고, 같은 프로젝트의 동일 파일·설정에 유효한 검사 결과가 있으면 재사용한다. 자동 전사나 발화 내용 검증을 수행했다고 주장하지 않는다. 검사 실패를 새 합성이나 유료 렌더로 해결하지 않는다.

전사 결과와 자막 시각은 실제 발화에 대조한다. 없는 단어·시각을 추측하지 않고 불확실한 부분은 미검증으로 남긴다. 원본을 덮어쓰거나 발화를 억지로 자르지 않는다. 호스트가 청취할 수 없다면 들었다고 보고하지 않는다.

## 창작과 제작

제품 원문의 확인한 주장·조건을 보존한다. 훅의 약속은 9초 이내에 완성하고 CTA가 이를 회수하게 한다. 나레이터·주인공·증인은 역할이며 고정 출연자 수가 아니다. 육도는 감정·행동 설계에 쓰고 영상 모델에 설명문으로 보내지 않는다. 승인된 인물·제품 참조로 원본 소재를 만들고 필요한 컷에 재사용한다. 24컷은 24번 유료 생성이 아니다.

먼저 한 나레이터가 읽을 정확한 대본 전문을 고객에게 보여준다. `plan.narratorScript={text,speakerId}`와 시간순 발화 비트를 일치시키고, 기존 승인 원문의 표현·수치·조건·시간을 자동 변경하지 않는다. 필요하면 고객 요청에 따른 별도 버전을 만들며 기존 원본을 보존한다.

새 영상은 [마스터카드와 실제 참조 양식](references/wow-master-card.md)을 읽고 `plan_save → direction_save → reference_prepare → storyboard_compile`로 준비한다. 등장 인물의 동일 카드 버전·실제 13구도·6표정, 실물 제품 원본, 세계관과 장면별 환경 이미지, 시작 프레임·렌즈·구도·카메라의 시작/행동/끝/이유를 연결한다. `reference_prepare`는 현재 입력 패킷을 동기화한 뒤 서버 Parzifal·Artemis를 실행한다. 고객 PC의 Python이나 복사한 행성 구현으로 영수증을 만들지 않는다. 준비 결과는 draft_prepared이며 사람 승인·제품 효능·유료 허가가 아니다. 제품 없는 창작은 products:[]와 noProductReason 및 기획의 claims:[]를 명시하고, 인물이 없으면 noCharacterReason을 남긴다. 사유만으로 실제 제품 광고의 근거를 면제하지 않는다.

동기화 대기는 반환된 `job_status`를 조회하고 행성 실행 대기는 같은 입력·requestId로 `reference_prepare`를 이어간다. 실패한 실행은 실패로 보존한다. 원인을 확인한 뒤 같은 입력의 무과금 준비를 새로 시작하는 경우에만 선택적 requestId에 새 UUID를 지정한다. 입력·대본·파일 변경 후 준비를 다시 검증한 다음 `storyboard_compile`의 실제 프롬프트를 확인하고 새 견적·접수를 진행한다.

연결된 프로젝트는 원본 소재를 project_sync로 저장하고 material_inspect의 해시 검증된 JPEG·무음 MP4를 실제로 본 뒤 material_review를 기록한다. pending이면 같은 인자로 재조회한다. 생성 원본을 완성 광고로 전달하지 않는다. 선택 음원·큰 구절 자막·제목·효과음을 edit_assemble로 조립한다. 가로/세로 모두 고정 서버 편집 계약을 사용한다. 기존 수동 코드는 체크포인트에 보존하고 연출을 확인한 뒤 명시적으로 전환한다.

project_sync → render_quote → 승인 범위 안의 render_start(final, quoteId) → render_status → render_download로 진행한다. 애매한 응답은 같은 작업 ID로 조회하며 새 유료 접수나 로컬 final로 대신하지 않는다. 연결된 프로젝트의 review_evidence는 이미 완료된 AWS MP4를 서버에서 검사하며 재업로드나 재렌더를 요구하지 않는다. pending이면 같은 인자로 재조회한다. 프레임·음량·무음·검은 구간 계측과 함께 MP4를 실제로 보고 들어 제품·발화·자막·호흡을 확인하고 필요한 구간만 수정한다. review_save는 실제 검수한 범위만 기록한다. project_publish와 독립 세션 복원 결과도 확인한다.

## 한국 릴스: 전체 길이와 제품 설득

한국어 릴스 기획에는 [한국 릴스 설득 가이드](references/korean-reels-grammar.md)와 [42초 전체 대본·동작표](references/42s-persuasion-example.md)를 먼저 읽는다. MCP에서는 creative_harness의 platform=reels가 이 두 문서를 반환한다.

고객이 지정한 본편 길이를 보존한다. 미지정 설명·구매형에는 3초 후킹 + 9초 공감 + 15초 제품 차이·원리·이점 + 10초 근거·구매 질문 + 5초 CTA의 42초 안을 제안하되 최적 공식으로 단정하지 않는다. 짧은 생성 원본이나 내부 시안을 본편으로 넘기지 않는다.

유명인 일반 발언은 문제·선택 기준으로 연결하고, 실제 제품 추천·고객 후기·제품 실증과 구분한다. 인물·원본·발언일·원문·맥락·제품 추천 여부를 확인한다. 우리 제품의 좋은 이유는 고객의 불편 → 기존 대처의 한계 → 확인된 제품 차이 → 작동 방식 → 입증 범위 안의 이점 → 적합 조건으로 쓴다.

이미지와 인물·소품 카드는 참조다. 실제 동영상에는 시작→행동→끝을 계획하고, 사진 줌을 사용 동작으로 대신하지 않는다. 최종 MP4와 소리에서 본편 길이·제품 설명·근거·CTA를 검수한다.

## 자료화면 기획에는 실제 이미지가 필수

사회적 증거·제품 원리·과학·생물학 자료화면을 설명하거나 기획할 때 **실제로 열 수 있는 이미지를 반드시 포함하고 고객에게 보여준다**. 글·프롬프트·카드 ID·영상 URL만 제시하는 것은 이미지 포함이 아니다.

- 각 자료화면에는 출처·원본 URL·관찰 시각이 있는 실제 참고 프레임 또는 자사 제품/시험/후기 원본 이미지를 붙인다. 새 영상 생성에는 해당 장면의 시작 상태를 보여주는 생성용 참조 이미지도 준비한다. 같은 이미지가 두 역할을 충족하면 재사용하고 기존 영상 재사용에는 그 원본의 대표 프레임을 사용한다.
- 고객에게 실제 이미지 미리보기를 표시하고 바로 아래에 무엇이 보이는지, 왜 이 발화에 필요한지, 시작→행동→변화→끝을 적는다. 출처와 역할(인용/후기/실증/개념/비유)을 함께 표시한다. 프롬프트만 있는 미생성 후보는 이미지 준비 완료가 아니다.
- 파일을 열어 실제 내용·제품 동일성·구도·원리 표현을 확인하고 이미지 파일·실제 해시·연결 장면을 현재 기획에 기록한다. 이미지가 없거나 열리지 않으면 해당 자료화면의 이미지 상태를 missing/unverified로 남기고 이미지 확보 단계로 이어간다. 텍스트 초안·피드백·기존 작업 조회는 가능하지만 그 자료화면의 기획 준비 완료나 새 영상 생성 준비 완료로 표시하지 않는다.
- 호스트가 이미지 생성을 지원하면 그 도구로 참조를 준비하고, 없으면 HIOB 이미지 견적과 기존 유효한 승인 범위로 준비한다. 이미지 필수 규칙 자체는 유료 호출·고객 확인을 대신하지 않는다. 실제 후기·시험·추천의 증거 이미지를 AI로 만들어 보충하지 않는다.
- 이미지로 구도와 시작 상태를 확인한 뒤 최종 자료화면은 실제 움직임과 상태 변화가 있는 영상으로 제작한다. 정지 사진의 줌만으로 사용/원리 동작을 대체하지 않는다. 원문 나레이션과 한 화자는 그대로 유지한다.


## 개인적 고통 하나
[고객 고통 선택 실행 지침](references/customer-primary-pain.md) 전문을 읽고 primaryPain·모든 beat.painLink를 저장한다. 고객에게 선택된 고통과 정확한 대본 전문을 보여주고 확인 전에도 피드백을 반영한다.


## 본능 설득과 상식 전복

고객 욕구와 구매 반론을 먼저 분석하고, 초반 전복 또는 후반 재해석을 제품 차이·근거·조건·CTA로 회수한다. [조사·작성·검수 기준](references/research-foundation.md)의 HIOB 광고 절과 [제작 실행 지침](references/production-workflow.md)을 읽는다. 한 나레이터와 고객에게 보여줄 정확한 대본 전문을 유지하고 기존 승인 원문을 자동 변경하지 않는다.


## 인물·브랜드·배경·카메라 필수 제작 계약 (2026-10-05)

모든 인물 컷(얼굴, 몸, 손 전용 포함)은 같은 참조 묶음과 컷별 연속성 검수를 사용한다. 화면에서 말하는 인물은 MiniMax H3 무음 원본 → 선택된 Typecast 승인 전문 음성의 구간 → Kling 립싱크 결과를 필수로 사용한다. 무발화 동작/손 전용 컷에도 인물·몸, 소품 브랜드, 배경 사용 흔적, 카메라 검수 네 항목을 강제한다.

1. 승인 원문·정확한 나레이터 전문·지정 목소리·타이밍을 잠근다. Meta Guide는 필재, LOTUS-Q의 기존 승인안은 서현 전문 음성이다. 다른 프로젝트의 보이스를 자동 상속하지 않는다.
2. 기존 인물 마스터 카드·13구도·6표정, 의상/시계/신발/손소품과 실제 제품 브랜드 원본, 배경의 공간 구조·광원·시간·날씨·사용 상태를 재사용한다. 필요한 얼굴/몸의 면과 제품 각도를 확보하고 실제로 본 자료만 관찰 완료로 기록한다. 참조 수를 줄이지 않는다.
3. 호스트가 각 `direction.assets[]`에 `humanActivity`(speaking/silent_action/hands_only/absent)와 `continuity`(personBody/propsBrand/backgroundUse/camera/stateBefore/stateAfter)를 파생한다. 브랜드 형태·로고·재질·크기·손 좌우·착용 위치와 분사/접촉/닦임/잔여 물기 등의 전후 상태를 연결한다. 동일 브랜드 설명·파일·해시를 고객에게 컷마다 다시 입력시키지 않는다. 카메라는 위치·높이·렌즈·프레이밍·시선·이동·종료 구도로 결박한다.
4. `reference_prepare`로 묶고 시작 프레임을 검수한 뒤 현재 승인 범위에서만 화면 원본을 생성한다. 화면 발화 지원은 단일 인물·5초·768p이며, 범위를 벗어나면 유료 생성 전에 구체적인 차단 사유를 반환한다. 승인 대사를 몰래 축약하거나 타이밍을 변경하지 않는다.
5. 화면 발화 원본 완료 후 `lipsync_prepare({projectId,assetId,jobId?})`를 호출한다. 원본·전문 음원의 서버 작업과 해시를 확인하고 PCM 구간·필요한 끝 무음·동기화를 자동 처리한다. 전송 중이면 같은 인자를 다시 조회하고 완료 시 반환한 `nextArgs`로 `lipsync_quote`를 호출한다. 새 합성·유료 접수는 하지 않는다. 음절이 잘리는 시간은 자동 추정으로 통과시키지 않는다.
6. 승인된 정확한 견적 범위에서 `lipsync_submit`하고 같은 작업 ID를 조회한다. `lipsync_download`의 `nextArgs`로 `material_inspect`하고 실제 소리 포함 결과와 동작을 관찰한다. `material_review`의 `humanPresence`, 실제 `observedHumanActivity`, `sceneChecks` 네 항목(person_body/props_brand/background_use/camera)을 기록한다. 화면 발화에는 `lipSyncChecks`의 speech/mouth_motion도 필요하다. 미확인을 pass로 만들지 않는다.
7. 검수한 결과로 조립하며 내장 후보 음성은 버리고 동일 승인 전문 음원을 한 번만 사용한다. 실제 발화·입모양·무음 구간과 몸/브랜드/배경/카메라, 최종 자막·편집을 검수한다. 서버도 실제 원본·전문·구간·립싱크 작업을 확인하므로 원본을 최종 발화 소재로 선택하거나 버전 숫자를 낮춰 우회할 수 없다.

Wow moment는 `spray then wipe` 같은 일반적인 제품 사용 문구만으로 준비 완료가 아니다. 고객의 예상과 시각적 전환, 제품 차이의 회수, 실제 근거와 AI 연출의 경계를 설명하고 실제 결과를 관찰한다. 보드 구조·참조 파일·기술 검사 통과는 창작 품질·고객 승인을 대신하지 않는다.

호출 예시:

```javascript
const prepared = await lipsync_prepare({ projectId, assetId: 'presenter' });
// 전송 중에는 prepared.nextTool/nextArgs 그대로 재조회한다.
const quoted = await lipsync_quote(prepared.nextArgs);
// 기존 사용자 승인/프로젝트 비용 범위 안에서만 접수한다.
const submitted = await lipsync_submit({ projectId, batchId: quoted.quote.id });
// lipsync_status로 동일 작업을 조회하고 succeeded jobId만 다운로드한다.
const output = await lipsync_download({ projectId, jobId });
const inspection = await material_inspect(output.nextArgs);
```

참조 검수는 호스트가 진행하고 고객에게 결과와 필요한 선택을 보여준다. SHA·경로 복사나 내부 도구의 연결 작업을 고객에게 떠넘기지 않는다. 얼굴 외 픽셀 동일성·자동 한국어 품질 합격을 보장하지 않는다. 원본·기존 승인·진행 중 작업을 보존한다.

## 큰 원본 파일

영상 원본과 프로젝트 동기화는 파일당 200MiB(209,715,200바이트)까지 지원한다. MCP가 8MiB 조각 전송과 전체 SHA 검증을 처리한다. 고객에게 수동 분할·압축·저화질 재생성을 요구하지 않는다. 기존 권한·승인·예산·선택 파일을 유지하며, 완료 후보의 다운로드는 편집 적용이나 품질 승인이 아니다. 화면 발화의 모델·음성 경로는 현재 model_catalog와 [제작 가이드](references/guided-production-guide.md)의 선택을 따른다.


## 오류 발생 시 코드별 복구

MCP 1.9.8에서는 error_recovery(code, projectId, failingTool?)와 hiob://error-recovery/{code}를 읽는다. [복구 사전](references/error-recovery.md)의 원인·담당·수정 단계·성공 확인에 따라 같은 프로젝트에서 이어간다. registered=false나 operator_diagnosis_required를 자동 해결로 보고하지 않는다. 기존 승인·음원·원본·작업 ID를 보존하고 새 증거 없이 유료 재접수하지 않는다.

Seedance 2/2.5 입력 참조는 실제 파일의 얼굴 유무를 확인하고 얼굴 없는 소품·배경을 사용한다. 생성 인물은 CHARACTER 텍스트로 묘사하며 인물 참조를 firstFrame으로 우회하지 않는다. 순정/native 및 lipsync의 기존 고객 선택·정확한 전문·목소리·타이밍은 유지한다. 실제 영상·음성 검수 없이 pass를 기록하지 않는다.

## 한도·사용량 질문 생략
고객에게 한도·사용량·총 예산 숫자를 묻지 않는다. 호스트가 connection_diagnose → production_check와 작업 status·quote로 서버 잔액·기존 승인 범위·현재 비용을 확인한다. 요청된 작업이 기존 승인 범위 안이면 반복 확인 없이 진행한다. 실제 부족·권한 제한만 구체적인 해결 행동으로 안내한다. 원문·목소리·한도·진행 중 작업은 보존한다.


## 오류 기록
막히면 error_gateway(historyOnly=true)에서 incidentId와 기존 job/request ID를 읽고 error_record로 복구 시도와 근거를 기록한다. 로컬 영속 기록이며 서버 공유를 보장하지 않는다. 복구 미검증 항목을 해결 완료로 표시하지 않는다.
