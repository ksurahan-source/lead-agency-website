# HIOB 영상 제작

사용자의 창작 방향·자료·기존 선택이 기준이다. 로컬 AI는 이해·기획·편집 판단을 맡고 Studio는 권한·버전·비용을 보관한다. 필요한 무거운 처리는 기존 서버·행성이 수행하며 최종 MP4는 Hephaestus → Remotion AWS Lambda가 만든다.

## 시작과 재개

설치된 도구 목록을 확인하고 기존 프로젝트의 project_context를 읽는다. workflow·productionGuide·판단 문서에서 현재 대사·선택 자산·음원·편집을 복원한다. 리소스를 열 수 없으면 [제작 절차](references/production-workflow.md)를 읽고 실제 도구 스키마를 확인한다. release_check는 공개/실행 버전, production_check와 render_status는 현재 서버·승인·한도를 확인한다. runtime_check는 클라이언트 조건만 확인한다.

같은 기기의 새 세션·호환 업데이트는 connection_resume으로 유효한 승인을 재사용한다. 같은 승인 범위 안에서는 단계별 새 동의를 요구하지 않는다. 실제 만료·철회·새 범위만 구분해 안내한다. 고객 승인 없이 권한·예산을 확대하지 않고 서버 오류를 재승인으로 해결하지 않는다. 고객에게 최종 렌더 엔진이나 컨테이너 설치를 요구하지 않는다.

## 목소리 선택

narrationSource에 recording·typecast·mixed를 보존한다. 녹음이 있으면 원본을 보존하고 실제 대사·길이·쉼을 먼저 확인해 장면과 구절 자막을 설계한다. audio_set은 직접 녹음도 연결하며 Typecast 합성 권한·비용이 필요하지 않다. 영상 생성과 최종 렌더 비용은 별도다. 녹음 모드에서는 합성 후보로 대체하지 않는다. 혼합은 요청한 문장만 AI 음성으로 보완한다.

연결된 프로젝트는 project_sync로 녹음부터 저장한 뒤 audio_inspect → audio_inspection_status로 같은 작업의 길이·음량·쉼을 확인한다. 초기 저장에 완성 대본이나 Reel.tsx는 필요하지 않다. 이 검사는 선택한 Typecast 후보·음악·효과음에도 필요하며 done 결과를 확인한 뒤 audio_set으로 연결한다. 검사는 원본 해시와 트림·속도·볼륨에 묶이므로 변경 후 다시 확인하고, 같은 프로젝트의 동일 파일·설정에 유효한 검사 결과가 있으면 재사용한다. 자동 전사나 발화 내용 검증을 수행했다고 주장하지 않는다. 검사 실패를 새 합성이나 유료 렌더로 해결하지 않는다.

전사 결과와 자막 시각은 실제 발화에 대조한다. 없는 단어·시각을 추측하지 않고 불확실한 부분은 미검증으로 남긴다. 원본을 덮어쓰거나 발화를 억지로 자르지 않는다. 호스트가 청취할 수 없다면 들었다고 보고하지 않는다.

## 창작과 제작

제품 원문의 확인한 주장·조건을 보존한다. 훅의 약속은 9초 이내에 완성하고 CTA가 이를 회수하게 한다. 나레이터·주인공·증인은 역할이며 고정 출연자 수가 아니다. 육도는 감정·행동 설계에 쓰고 영상 모델에 설명문으로 보내지 않는다. 승인된 인물·제품 참조로 원본 소재를 만들고 필요한 컷에 재사용한다. 24컷은 24번 유료 생성이 아니다.

연결된 프로젝트는 원본 소재를 project_sync로 저장하고 material_inspect의 해시 검증된 JPEG·무음 MP4를 실제로 본 뒤 material_review를 기록한다. pending이면 같은 인자로 재조회한다. 생성 원본을 완성 광고로 전달하지 않는다. 선택 음원·큰 구절 자막·제목·효과음을 edit_assemble로 조립한다. 가로/세로 모두 고정 서버 편집 계약을 사용한다. 기존 수동 코드는 체크포인트에 보존하고 연출을 확인한 뒤 명시적으로 전환한다.

project_sync → render_quote → 승인 범위 안의 render_start(final, quoteId) → render_status → render_download로 진행한다. 애매한 응답은 같은 작업 ID로 조회하며 새 유료 접수나 로컬 final로 대신하지 않는다. 연결된 프로젝트의 review_evidence는 이미 완료된 AWS MP4를 서버에서 검사하며 재업로드나 재렌더를 요구하지 않는다. pending이면 같은 인자로 재조회한다. 프레임·음량·무음·검은 구간 계측과 함께 MP4를 실제로 보고 들어 제품·발화·자막·호흡을 확인하고 필요한 구간만 수정한다. review_save는 실제 검수한 범위만 기록한다. project_publish와 독립 세션 복원 결과도 확인한다.

## 결과 보고

소스 검사, 배포, 실제 서버 영상, 실제 고객 환경, 창작 검수를 각각 구분한다. 스킬이나 테스트 통과만으로 영상 품질·광고 성과를 보장하지 않는다. MCP 1.3.11 베타 / 스킬 1.3.11: 공개 여부와 실제 사용 가능 범위는 현재 서버 응답으로 확인한다. Windows 실기기와 승인된 AWS MP4의 종단 간 성공은 검증 대기다. 미디어 검사 서버 연결이 준비되지 않았다면 그 부분을 완료로 소개하지 않는다.

MCP에서는 hiob://inspection-guide로도 읽을 수 있다.

## 프로젝트 간 소재 공유

[애셋 라이브러리 안내](references/asset-library-guide.md)를 읽는다. Studio 계정 라이브러리에서 같은 작업공간의 프로젝트 사이로 추가·이동한다. 대상 프로젝트의 MCP 연결로 공유 이미지·문서를 읽고 해시를 확인한다. 공유 영상은 원본 프로젝트 jobId로 검사하지 않는다. 편집 자료에 명시적으로 가져온 새 저장 버전을 복원하며, 기존 로컬 작업은 먼저 저장한다.


## 한국 릴스: 전체 길이와 제품 설득

한국어 릴스 기획에는 [한국 릴스 설득 가이드](references/korean-reels-grammar.md)와 [42초 전체 대본·동작표](references/42s-persuasion-example.md)를 먼저 읽는다. MCP에서는 creative_harness의 platform=reels가 이 두 문서를 반환한다.

고객이 지정한 본편 길이를 보존한다. 미지정 설명·구매형에는 3초 후킹 + 9초 공감 + 15초 제품 차이·원리·이점 + 10초 근거·구매 질문 + 5초 CTA의 42초 안을 제안하되 최적 공식으로 단정하지 않는다. 짧은 생성 원본이나 내부 시안을 본편으로 넘기지 않는다.

유명인 일반 발언은 문제·선택 기준으로 연결하고, 실제 제품 추천·고객 후기·제품 실증과 구분한다. 인물·원본·발언일·원문·맥락·제품 추천 여부를 확인한다. 우리 제품의 좋은 이유는 고객의 불편 → 기존 대처의 한계 → 확인된 제품 차이 → 작동 방식 → 입증 범위 안의 이점 → 적합 조건으로 쓴다.

이미지와 인물·소품 카드는 참조다. 실제 동영상에는 시작→행동→끝을 계획하고, 사진 줌을 사용 동작으로 대신하지 않는다. 최종 MP4와 소리에서 본편 길이·제품 설명·근거·CTA를 검수한다.


## 제품·과학 장면과 배속

장면을 만드는 방법은 [제품·과학·생물학 장면 제작 가이드](references/product-science-scenes.md), 실제 도구로 실행하는 방법은 [MCP 실행 지침](references/product-motion-execution.md)을 읽습니다. 느린 외부 나레이션은 1.05–1.2배를 비교하되 바뀐 설정으로 음원 검사를 다시 하고 자막을 재조정합니다. 현재 MCP는 음성 playbackRate만 지원하며 영상 컷 배속은 지원하지 않습니다. 입모양이 있는 컷은 음성만 가속하지 않습니다. 지정된 본편 길이는 보존합니다.

## 자료화면 기획에는 실제 이미지가 필수

사회적 증거·제품 원리·과학·생물학 자료화면을 설명하거나 기획할 때 **실제로 열 수 있는 이미지를 반드시 포함하고 고객에게 보여준다**. 글·프롬프트·카드 ID·영상 URL만 제시하는 것은 이미지 포함이 아니다.

- 각 자료화면에는 출처·원본 URL·관찰 시각이 있는 실제 참고 프레임 또는 자사 제품/시험/후기 원본 이미지를 붙인다. 새 영상 생성에는 해당 장면의 시작 상태를 보여주는 생성용 참조 이미지도 준비한다. 같은 이미지가 두 역할을 충족하면 재사용하고 기존 영상 재사용에는 그 원본의 대표 프레임을 사용한다.
- 고객에게 실제 이미지 미리보기를 표시하고 바로 아래에 무엇이 보이는지, 왜 이 발화에 필요한지, 시작→행동→변화→끝을 적는다. 출처와 역할(인용/후기/실증/개념/비유)을 함께 표시한다. 프롬프트만 있는 미생성 후보는 이미지 준비 완료가 아니다.
- 파일을 열어 실제 내용·제품 동일성·구도·원리 표현을 확인하고 이미지 파일·실제 해시·연결 장면을 현재 기획에 기록한다. 이미지가 없거나 열리지 않으면 해당 자료화면의 이미지 상태를 missing/unverified로 남기고 이미지 확보 단계로 이어간다. 텍스트 초안·피드백·기존 작업 조회는 가능하지만 그 자료화면의 기획 준비 완료나 새 영상 생성 준비 완료로 표시하지 않는다.
- 호스트가 이미지 생성을 지원하면 그 도구로 참조를 준비하고, 없으면 HIOB 이미지 견적과 기존 유효한 승인 범위로 준비한다. 이미지 필수 규칙 자체는 유료 호출·고객 확인을 대신하지 않는다. 실제 후기·시험·추천의 증거 이미지를 AI로 만들어 보충하지 않는다.
- 이미지로 구도와 시작 상태를 확인한 뒤 최종 자료화면은 실제 움직임과 상태 변화가 있는 영상으로 제작한다. 정지 사진의 줌만으로 사용/원리 동작을 대체하지 않는다. 원문 나레이션과 한 화자는 그대로 유지한다.
