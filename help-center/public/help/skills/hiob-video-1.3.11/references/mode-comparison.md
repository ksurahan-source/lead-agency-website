# 비교형 에이전트 MD

이 구조는 공식 플랫폼/AI 제작 근거를 종합한 HIOB 창작 운영 권고다. 비교형 자체가 알고리즘 우대나 바이럴 성공을 보장하지 않는다. 선택한 플랫폼 MD와 함께 읽는다.

## 사용할 때와 경계

같은 기준·조건에서 차이를 자료나 관찰로 보여줄 수 있을 때. 합성 이미지를 실제 성능 증거로 쓰지 않는다.

## 구조와 훅 후보

비교 질문 → 동일 조건/기준 → A/B 관찰 → 차이/한계 → 조건부 추천

비슷해 보이는 두 결과의 차이 / 타깃 상황에 따라 달라지는 선택 / 핵심 기준 한 가지. 근거 없는 절대 우위를 제목으로 만들지 않는다.

첫 화면·정확한 첫 대사/자막·시청자가 기다릴 질문·회수할 마지막 장면을 함께 적는다. 보조 기법은 한 개를 정하고 주 모드의 구조를 유지한다. 원문 브랜드 메시지·숫자·표현을 보존한다.

## 기획 이미지와 카드

제품·도구와 전후 상태를 소품 카드로, 같은 촬영 구도·빛·시간·측정 조건을 배경 카드로 유지한다. 인물이 필요하면 동일 역할/행동을 고정한다. 측정값·자료화면 출처·조건을 표시한다.

실제 기획 이미지3장과 별도 인물/상황소품/배경 카드를 보여준다. 인물은 계정 보관함의 정확한 버전·해시를 재사용하고 새 얼굴을 자동 생성하지 않는다. 장면별 카드 ID와 보존 특징을 프롬프트의 실물 설명으로 번역한다. 없는 이미지/카드는 missing으로 알리고 계속 기획한다. 호스트 이미지 생성이 없으면 image_generation_status → image_generation_quote로 PiAPI 대안을 안내하며 사용 승인·견적 없이 접수하지 않는다.

## 소리·자료 화면·극적 요소

A/B 대사를 분리하고 효과음·음악이 한쪽만 유리하게 느끼게 만드는지 확인한다. 설명과 실제 관찰 소리를 구분한다.

모델별 promptGuidance를 읽고 H3/Seedance 문법을 섞지 않는다. 자료 화면은 맥락·행동·근거 확인의 역할을 갖고 원문과 연결한다. VFX·특수음악·편집 전환은 사건의 기대와 보상을 만들 때 사용한다.

## 초안 비평와 수정본 재검토

유리한 조건의 한쪽만 보여줌, 단위/기준 없음, AI 결과를 실제 실험처럼 꾸밈, 결론의 조건 삭제를 고친다.

초안에서 두 문제를 구체적 장면으로 적고 실제 visual/narration/caption/CTA를 고쳐 before/after와 이유를 남긴다. 수정본과 실제 이미지 확인 범위를 다시 기록한다. AI 검토는 인간 승인으로 기록하지 않는다. 누락은 경고이며 진행을 막지 않는다. 실제 원본과 최종 MP4를 본 뒤에만 영상 품질을 평가한다.

## 게시 후 검증

기준 이해와 상황별 질문을 확인한다. 조건·표본이 다르면 단일 승자를 선언하지 않는다.

훅·보상·길이·자료 화면 중 하나만 바꾸는 비교 가설과 관찰 시점을 적는다. 자동 게재·자동 유료 재생성은 이 문서가 승인하지 않는다.

## 근거와 해석

- [YouTube Shorts 추천 원리](https://support.google.com/youtube/answer/11914225?hl=en): 추천 신호이며 특정 모드의 효과 증명이 아니다.
- [Google ABCD 광고 제작 원칙](https://support.google.com/google-ads/answer/14783551?hl=en): Attention/Branding/Connection/Direction을 목표에 맞게 적용한다. 광고와 유기적 추천을 분리한다.
- [Runway 영상 프롬프트 가이드](https://help.runwayml.com/hc/en-us/articles/39789879462419-Gen-4-Video-Prompting-Guide): 단순 동작에서 시작해 관찰하며 수정하는 모델별 지침. HIOB에 Runway가 연결돼 있다는 뜻이 아니다.
- [AI 기획 리서치](research-foundation.md): 확인 날짜와 공식 사실/운영 권고를 구분한다.
