## 고객 선택을 기본 허용하는 제작 정책 (2026-10-09)

한 나레이터는 기본 권장이다. 고객이 2인 대화와 MiniMax 순정 음성을 선택하면 그 선택으로 진행한다. 대본 전문은 하나로 유지하고 대사별 `beat.speakerId`를 `direction.speakers.castId`와 연결한다. `narratorScript.speakerId`는 생략된 beat의 기본 화자이며 모든 화자를 한 사람으로 합치는 명령이 아니다. native 경로에 Typecast voiceId·한 얼굴·Kling 후처리를 요구하지 않는다. 서로 다른 대사와 화자, 화면의 청자를 구분하고 실제 두 목소리·입모양·얼굴·연기를 검수한다.

기획·자료 준비·저장·조회·독립 작업은 기본 허용한다. 실제 권한 없음/비용 승인 범위 초과, 원문·타이밍·선택 화자 무단 변경, 파일/참조 무결성 불일치, 해당 제공사 단계의 확인된 입력 제한, 중복 유료 접수, 관찰 없는 품질 합격을 금지한다. 단일 얼굴 원본·5초·Typecast 요구는 현재 Kling 립싱크 경로의 제약이며 MiniMax 순정 2인 생성에 전역 적용하지 않는다. 복수 화자 전체 혼합 음원을 단일 화자 클로닝에 제출하지 않는다. Seedance 입력 참조 얼굴 제외·CHARACTER 150단어는 유지한다. 기존 성공 자료와 작업·원문을 일괄 무효화하지 않는다. 오류 코드는 정확한 사건 검색용으로 유지하고 호스트가 같은 ID로 구체적인 원인/해결을 처리한다.


# 제품 설명에 이유가 있는 움직임

움직임이 고객 질문을 해결하거나 제품 동작·차이·근거를 보여주는지 먼저 판단한다. 모든 컷에 mesh·grain·glow·Ken Burns·stagger를 강제하지 않는다. 정지 hold도 라벨과 조건을 읽게 하는 유효한 연출이다.

## 기획에서 실행으로

1. `project_context`의 승인 대본/보드, 비율·브랜드·소품/배경·목소리/타이밍·기존 성공 자산을 읽는다. 이미 선택한 화면비/배경/스타일을 다시 묻지 않는다. 실제 스크린샷·제품 사진과 사용 권한을 연결한다. 가짜 제품 화면이나 허구의 고객 증거로 빈 화면을 채우지 않는다.
2. 설명할 핵심 하나를 고르고 **hold→정보/동작 변화→읽을 수 있는 hold**로 큐를 만든다. 승인 카메라가 고정이면 임의로 이동시키지 않는다. 그림/자막/소리 각 층의 시작·끝은 실제 승인 음성 구간에 결박한다.
3. `creative_catalog`의 현재 feature status와 inputSchemas를 읽고 `references/execution-and-review.md`로 실행을 분기한다. 기획표 항목은 제작 도구의 새 필드가 아니다.

## 고객에게 보여줄 모션 큐

문장/컷 ID, 원본 자산 경로와 hash, 설명 목적, 시작/끝 시간, 주요 변화 하나, 초점·읽기 hold, 소리 큐, 보존할 라벨/숫자/형태/카메라, 현재 실행 가능 여부를 표로 반환한다. 소품 접촉·획득·전달 전후 상태를 연결한다. 새 효과 후보를 기존 성공 자산과 분리한다.

지원되는 제목/자막과 시간 지정 flash/vignette/zoom, 로고, brightness/contrast/saturation은 현재 `edit_assemble`/`edit_check` 스키마로 처리한다. 승인 고정 카메라나 제품 라벨 hold를 침범하는 zoom을 지원 여부만으로 적용하지 않는다. 음악·효과음은 현재 `audio_set` 전체 트랙 교체 계약을 읽고 기존 발화를 포함해 보존한다. `audio_export`는 영상 보존 음향 파생본이며 영상 모션 구현 도구가 아니다.

자유로운 path animation·custom overlay·counter·mask·parallax는 현재 MCP v1의 편집 필드로 전송하지 않는다. 실제 Remotion 소스 프로젝트를 개발할 때만 기존 `remotion-video-creation` 스킬과 설치된 런타임의 공식 API를 확인해 코드 후보를 구현한다. HIOB 고객이 그 후보를 저장/미리보기/재개/렌더할 수 있는 소비자와 등록 경로가 확인되지 않으면 **구현 후보/미연결**로 남긴다. 운영자 로컬 MP4를 고객 셀프서비스의 증거로 부르지 않는다.

## 검수

실제 재생 영상과 음성을 보고 읽기 시간, 제품 라벨/숫자, 타이포 잘림, 안전 영역, 동작 시작/끝, 인접 컷 상태, 원래 음성 전문·동기화·카메라를 확인한다. 프레임 한 장이나 JSON 점수를 영상 전체 품질로 해석하지 않는다. 본 시간 구간·원본과 결과 hash·문제/수정·미관찰을 기록하고, 수정 후보만 재검수한다.

원본/승인 전문/타이밍은 자동 교체하지 않는다. 기존 유료 job 상태를 확인한 뒤 승인 범위 안에서만 실제 작업을 진행한다. 부족한 크레딧 숫자를 고객에게 묻지 않는다. GitHub 채택 원칙과 충돌은 `references/source-attribution.md`를 읽는다.
