# HIOB 사운드·제목·반응 편집

고객 메시지가 선명하게 느껴지는 광고를 만든다. 모든 컷에 효과를 넣는 것을 완성 기준으로 삼지 않는다. 초반 9초 안에 관심과 필요성을 전달하고, 3–5초 의미 묶음을 기본 편집 단위로 사용하되 실제 발화·증거를 자르지 않는다.

## 인물·음향·극적 전개·자료 화면을 함께 기획한다

제작을 시작할 때 다음 기준을 고객에게 안내하고, 장면별 편집표에 선택 이유와 시각을 기록한다. 실제 영상·청취 전에는 적용 계획과 확인한 결과를 구분한다.

1. **영상 속 소리와 별도 나레이션을 구분한다.** 화면 속 인물의 대사, 현장·동작음, 화면 밖 나레이터, 배경음악, 효과음을 따로 설계한다. 사람이 등장하는 컷마다 누가 말하는지, 입이 움직이는지, 원본에 대사가 있는지 확인한다. 화면 속 대사는 dialogue, 외부 해설은 narration으로 연결한다. 인물이 말하는 것처럼 보이는데 다른 나레이터의 소리가 붙거나 두 발화가 겹치지 않도록 한다. 외부 해설 컷은 필요하면 입이 움직이지 않는 반응·행동 화면을 선택한다. 원본 대사는 승인 없이 지우지 않는다. 원본 영상에 포함된 소리를 자동 보존한다고 가정하지 말고 최종 믹스에 실제 연결됐는지 확인한다.
2. **음악은 장면 분위기와 이야기 흐름에 맞춰 고른다.** 긴장·고민·발견·안도 등 구간의 감정, 브랜드 인상, 템포와 악기, 발화 명료도를 기준으로 선택 이유를 적는다. 라이브러리 검색 제목만 보고 적합하다고 판단하지 않는다. 실제로 듣고 음악이 대사·나레이션을 덮지 않는지 확인한다.
3. **특수효과·효과음·짧은 음악 효과를 계획한다.** 문제의 강조, 발견, 전환, 해결에 맞춰 시각 효과와 클릭·임팩트·우시 등 효과음, 라이저·스팅어 같은 음악 효과의 위치와 목적을 지정한다. 사용할 실제 소재와 지원 경로를 확인한다. 모든 컷에 같은 효과를 반복하지 않는다. 현재 MCP의 임의 줌·흔들림·글리치·GIF 레이어는 미지원이므로 가능한 효과가 포함된 소재나 확인된 편집 기능을 사용하고, 구현하지 못한 효과는 미적용으로 기록한다.
4. **극적인 요소를 갖춘다.** 구체적인 불편·갈등 → 긴장 또는 기대 → 발견·전환 → 해결·행동으로 감정의 변화와 장면의 보상을 만든다. 표정·행동·컷 대비·잠깐의 정적·음악 변화로 강조하고, 효과만 늘려 밋밋한 이야기를 덮지 않는다. 사실이나 수익을 과장해 긴장감을 만들지 않는다.
5. **중간중간 자료 화면을 넣는다.** 인물과 설명만 이어가지 말고 설명·전환·증거 구간 사이에 실제 제품 화면, 사용 장면, 문서·표·도표, 관련 디테일 컷을 배치한다. 각 삽입의 목적, 시작·종료 시각, 출처와 주장 연결을 적는다. 무관한 장식 화면을 억지로 넣지 않는다. 메타가이드는 실제 수수료·환급 조건 자료와 허용된 서비스 화면을 우선하고, 생성 화면을 실제 계좌·거래·환급 증거로 제시하지 않는다.

최종 검수는 소리를 켜고 인물의 발화·입 움직임, 대사와 나레이션의 중복·누락, 현장음, 음악 분위기·음량, 효과의 타이밍·극적 전환을 확인한다. 무음으로 자료 화면의 가독성·출처·설명 연결과 장면 흐름도 확인한다. 누락·미지원·미청취 항목을 남기며 체크리스트의 존재만으로 완성 영상 품질을 합격 처리하지 않는다.

## 먼저 실제 기능을 확인

`project_context(projectId)`의 전체 Vault를 읽고 `creative_catalog`에서 이번 MCP의 실제 편집·음원 스키마와 지원 경계를 확인한다. 기능 목록이나 검색 성공은 AWS MP4 성공이 아니다. 현재 MCP V1 제목은 top/middle, 자막은 lower/middle, 제목 스타일은 basic/question/info/cta다. 현재 V1은 자동 제목 진입 모션만 있으며 임의 줌·흔들림·글리치·스티커 레이어 필드를 만들지 않는다. Studio V2에 코드가 있어도 현재 고객 MCP 경로에서 쓸 수 있다는 뜻은 아니다.

## 기존 화면에 음향만 추가할 때

기존 화면·내장 자막·길이를 그대로 유지하는 요청이면 일반 `edit_assemble → render_start` 대신 `audio_export`를 사용한다. 일반 렌더는 화면을 다시 인코딩하며 크기·fps를 변경할 수 있다. source-review/visual-only 등 검수 프록시나 이미 압축한 파생본을 원본으로 고르지 않는다. 업로드한 실제 원본의 SHA-256을 확인한다.

1. 원본과 이용 가능한 음원을 `project_sync`로 저장한다. 현재 각 파일 200MiB·영상 10분·트랙 32개 이내다. 큰 원본을 한도에 맞추려고 낮은 화질로 바꾸지 말고 지원 한도를 알린다. MP4/MOV 안의 H.264/HEVC/AV1 단일 영상 트랙을 지원하며, 지원되지 않는 형식은 명시적 오류로 중단한다.
2. 원래 소리를 유지하며 더할 때 `sourceAudio="mix"`, 교체할 때만 `"replace"`를 사용한다. 원래 대사를 임의 삭제하지 않는다. 기본 sourceGainDb=0이고, 조정은 요청과 실제 청취에 따른다.
3. `audio_export(projectId,requestId,sourceSha256,sourceAudio,tracks)`에 음원별 sourceSha256/startSec/trimStartSec/trimEndSec/gainDb를 지정한다. trimEndSec는 음원 안의 종료 시각이다. 이 모드만 fadeInSec/fadeOutSec를 지원하며, 일반 V1 audio_set에 필드를 옮겨 넣지 않는다. 발화 트랙은 끝 음절을 포함하도록 길이를 확인한다.
4. 같은 작업은 같은 requestId로 재조회한다. `audio_export_status`의 done과 videoPreserved=true를 확인한 뒤 `audio_export_download`로 결과·preservation.json을 받는다. 영상 패킷·타임스탬프·표시 메타데이터가 다르면 완료되지 않는다. 원본보다 긴 트랙은 자동으로 잘라내지 않는다.
5. 결과의 원래 소리·추가 발화·음악 균형·끝 음절을 청취한다. 기술적 동일성은 음향/창작 품질 합격이 아니다. 새 자막·제목·크롭·화면 효과를 넣는 요청에는 원본 보존을 약속하지 말고 일반 편집 경로를 쓴다.

## 편집표부터 만든다

각 의미 묶음에 다음을 적는다.

| 시간 | 전달할 의미/발화 | 화면 사건 | 제목 | 음악 | 효과음 | 반응 소재 |
|---|---|---|---|---|---|---|
| 훅 | 누구의 어떤 불편인지 | 불편이 드러나는 행동 | 발화를 반복하지 않는 관점 | 첫 박자와 에너지 | 사건 하나에 대응 | 이해에 도움이 될 때만 |
| 설명·증거 | 제품이 등장할 이유 | 사용/실제 자료 | 용도·조건 | 발화 명료도 우선 | 클릭·확인·리빌 등 | 증거나 고객 경험으로 오인시키지 않기 |
| CTA | 다음 행동 | 처음 불편과 연결 | 구체적인 행동 문구 | 자연스러운 종결 | 필요하면 한 번 | 불필요하면 없음 |

음악=장면을 잇는 에너지, 효과음=화면 사건, 제목=구간의 관점, 자막=실제 발화다. 같은 기능을 여러 층이 중복해서 소란스럽게 만들지 않는다. 六道 감정과 선택한 인물/브랜드 스타일은 기존 Vault를 따른다.

## 음악·효과음의 실행 경로

1. `sound_library(projectId, category="music" 또는 "sfx", query, offset, limit)`로 기존 HIOB 공용 라이브러리를 찾는다. 검색은 제목 기준이며 권리·실제 음량을 보증하지 않는다. 결과가 없으면 검색어를 바꾸거나 고객이 제공한 이용 가능한 파일을 사용한다. 존재하지 않는 라이브러리 곡을 발명하지 않는다.
2. 선택한 ID를 `sound_import(projectId,itemId,expectedSha256?)`로 가져온다. 반환된 file/sha256을 사용한다. 가져오기는 트랙 선택이나 합성이 아니다. source.json의 출처 기록을 보존한다.
3. `project_sync` 완료 후 `audio_inspect`와 `audio_inspection_status`로 길이·음량을 확인한다. 직접 녹음은 원본·실제 발화·쉼을 기준으로 유지한다. Typecast로 임의 교체하지 않는다.
4. `audio_set`은 **전체 tracks 교체**다. 기존 audio.json의 narration/dialogue/music/sfx를 읽고 유지할 트랙에 새 트랙을 합친다. 음악만 보내 음성을 지우지 않는다. role, startSec, trimStartSec/trimEndSec, playbackRate, gainDb는 creative_catalog의 실제 스키마를 사용한다.
5. 음악을 컷마다 다시 시작하지 않는다. 효과음은 화면 사건 시각에 배치한다. 현재 V1 API에는 fade/ducking envelope 입력이 없다. 해당 필드를 임의 추가하지 않는다. 필요한 페이드·감쇠는 이용 가능한 원본을 보존한 별도 처리 파일로 제공하고 동일 파일을 선택해야 한다. 처리 도구가 없으면 미지원으로 표시한다.
6. 작은 PCM WAV는 필요할 때 `audio_gain`으로 파생본을 만든다. 파생본에 원래 증폭을 또 적용하지 않는다. 숫자만 맞추지 말고 발화·음악 존재감을 실제로 비교 청취한다.

## 제목과 자막

제목은 captions가 아닌 edit.titles에 넣는다. `top` 제목 + `middle` 정보 + `lower` 발화는 실제 영역이 충돌하지 않을 때 함께 쓴다. 기본·질문·정보·CTA 스타일과 direction_save의 standard/large(1.15배) 글자 프리셋을 활용한다. 큰 제목으로 얼굴·제품을 가리지 않는다. 실제 발화는 의미 구절 1–2줄로 나누고 문장 끝을 보존한다. `edit_check`의 충돌·중복 오류를 문구/배치/시간으로 고친다. 자막을 지워 검사를 통과하지 않는다.

## 짤·GIF·스티커

`reaction_search(provider="klipy" 또는 "giphy",query,kind="gifs" 또는 "stickers")`는 공식 API의 검색·미리보기 전용이다. MCP 실행 환경에 해당 API 키가 필요하다. 키를 채팅·기획서·프로젝트에 저장하지 않는다. 검색 결과의 순서·광고·원본 URL·출처를 보존하고 제공사별로 따로 보여준다.

검색 가능과 광고 재편집 권리는 다르다. 원격 결과를 자동 다운로드·재호스팅·AWS MP4에 삽입하지 않는다. KLIPY의 서버 프록시·미디어 저장 등 별도 승인이 필요한 사용은 개발자 승인 범위를 확인한다. 실제 광고에는 고객이 권리를 확인한 파일이나 직접 만든 반응 컷을 사용한다. 현재 V1에서 GIF/투명 애니메이션 오버레이는 미지원이며, 사용 가능한 MP4 반응 컷은 기존 소재 등록/연출·검수 경로로 넣는다. 이를 제품 효과나 실제 고객 증언으로 표현하지 않는다.

## 조립·검수

`edit_check → edit_assemble → job_status(completed) → project_sync` 순서로 같은 버전을 준비한다. 새 영상·음성 생성 없이 음악·제목·컷 선택만 바꿀 수 있다. 유효 권한·견적 범위 안에서만 AWS 최종 렌더를 접수한다. 마지막에는 무음으로 제목/자막/의미를, 소리 켜고 발화/음악/효과음/끝 음절을 검사한다. 원본의 파일·해시·대사·권리 출처와 결과 버전을 함께 보존한다.

## 여러 자료의 검사와 대기

검사는 워크스페이스 전체에서 미완료 10,000개, UTC 하루 신규 접수 10,000개·재시도 포함 실행 10,000회를 공유한다. 전체 서버는 실제 4개씩 병렬 처리하며 나머지는 큐에서 기다린다. 일일 한도는 UTC 00:00(한국 09:00)에 초기화된다. pending은 실패가 아니다. 오디오는 반환된 jobId로 audio_inspection_status를 조회하고 영상·최종본은 같은 검사 도구와 인자를 약 60초 간격으로 다시 호출한다. requestId·jobId·원본 해시·검사 설정을 보존하며 대기 중 새 생성이나 렌더를 요청하지 않는다. 한도 오류와 실행 순서는 MCP 리소스 `hiob://inspection-guide`를 읽는다. 완료 결과의 재사용도 현재 프로젝트 권한·원본·설정 일치를 확인한다. 검사 수치만으로 창작 품질을 합격 처리하지 않는다.

## 느린 발화와 제품·원리 영상

영상 동작이나 발화가 느리면 1.05~1.2배속을 비교하도록 권장한다. 음성은 1.05 또는 1.1부터 듣고 명료할 때만 더 올린다. 발음 오류는 원문/원본을 먼저 고친다. creative_catalog.executionGuide의 MCP 실행 지침에 따라 같은 배속으로 재검사하고 기존 전체 트랙·자막 타이밍을 보존한다. 현재 영상 컷 배속과 audio_export의 배속 입력은 미지원이며 화면 인물의 대사를 소리만 가속해 립싱크를 깨지 않는다. 인물 외 매크로·과학·생물학 장면의 구성과 예시는 creative_harness(platform=reels)의 product-science-scenes 문서를 읽는다.

## 인물이 등장하는 모든 컷의 육도 연기 (2026-10-08)

**모든 인물 컷은 육도 감정이 표정·시선·자세·손·움직임에 보여야 한다. 이미지의 감정이 영상·립싱크·최종 편집에서 사라지면 통과가 아니다.** 호스트가 저장된 `direction.assets[].realm/expression/action`을 읽어 장면의 시작 → 주요 행동 → 반응으로 연결한다. 지옥은 압박과 긴장, 축생은 두려움과 방어, 아수라는 경쟁과 좌절, 인간은 분투와 의심, 아귀는 갈망과 기대, 천상은 얻어낸 안도다. 한 컷에 한 감정을 출발점으로 삼고 기존 승인 연출을 우선한다.

손 전용 컷은 손의 긴장·속도·주저함/확신으로 표현한다. 인물 없는 컷에 사람을 추가하지 않는다. Seedance의 CHARACTER 150단어와 얼굴 없는 참조 규칙을 유지하고 연기는 SCENE AND ACTION에 둔다. 같은 나레이터·승인 전문·목소리·타이밍을 보존하며 감정 보완을 이유로 기존 음원을 자동 재합성하지 않는다.

`storyboard_compile`의 실제 prompt에 의도가 전달됐는지 확인한다. 이후 원본 영상과 립싱크 결과를 실제로 보고 `material_review.sceneChecks`의 `person_body.note`에 타임코드·의도·관측된 연기·손상 여부를 기록한다. 최종 MP4에서도 같은 컷을 다시 본다. 프롬프트 전달, 실제 표현, 립싱크 후 보존은 별도 판정이다. 누락 시 원본 연출과 해당 소재를 읽어 보완하고 기존 성공 소재를 재사용한다. 관찰 없이 pass를 만들거나 무표정 포트레이트로 대체하지 않는다. 막힌 경우 `error_record`에 같은 작업/incident ID와 복구 결과를 남긴다.
