# HIOB 영상 제작

고객의 자료와 의도가 기준이다. 고객이 기획, 목소리와 비용을 검토하고 필요한 부분을 고친다. 이 스킬을 읽는 것은 영상 생성이나 결제 승인 자체가 아니다.

1. 설치된 HIOB MCP의 도구 목록과 최신 `workflow` 리소스를 읽는다. 실행 앱의 리소스 API로 열리지 않으면 [제작 지침](references/production-workflow.md)을 읽고 실제 도구 스키마를 확인한다. 도구가 없으면 설치 도움말 https://hi-ob.com/help 로 안내한다. 로컬 파일 경로나 공급자 키를 추측하지 않는다.
2. 첫 유료 작업 전에 `runtime_check`, 프로젝트 연결, 원본 복원, 크레딧과 실행 한도를 확인한다. Windows는 Codex와 MCP가 같은 환경에 설치되어야 하며 렌더에 Docker가 필요하다. 권한 차단을 무음 MP4나 다른 프로젝트로 우회하지 않는다.
3. 사용 목적, 대상, 길이, 화면비, 확인된 제품 근거, 마지막 행동을 정리한다. 모르는 사항만 묻는다. 기획·대본·장면별 소리와 비용을 먼저 보여준다. 확인되지 않은 효능이나 체험담은 넣지 않는다.
4. 첫 3초에 대상·문제·발견을 전달하고 9초 안에 훅의 약속을 완성한다. 나레이터는 가이드, 주인공은 시청자의 상황을 보여준다. 다인물은 의미가 있을 때만 사용한다. 육도 감정과 표정·배경·제품 연속성을 설계한다. 컷 수와 원본 생성 수를 혼동하지 않는다.
5. 짧은 음성 후보 하나를 먼저 실제로 청취해 말의 속도·강세·제품명 발음을 확인한다. 고객 승인 후 필요한 문장만 합성한다. 주인공 대사와 외부 나레이션을 구분한다. 고객 녹음도 소스로 쓸 수 있다. 음성 누락을 배경음악으로 가리지 않는다.
6. 이미지 생성은 현재 AI 앱에서 사용 가능한 이미지 도구와 이용 조건을 확인한 뒤 실행한다. HIOB MCP 설치만으로 Codex 이미지 생성 기능을 추가하거나 구독 권한을 보장하지 않는다. 승인된 인물 참조와 실제 제품 자료를 사용하고, 합성 장면을 실제 효과의 증거로 표시하지 않는다.
7. 실제 발화 길이에 맞춰 컷, 큰 구절 자막, 제목, 음악 감쇠, 효과음을 조립한다. 중요한 제품 동작을 가리지 않는다. 대본·음원·자막 버전을 맞추고 마지막 음절을 자르지 않는다. 저장한 편집 프로젝트와 같은 소스로 렌더한다.
8. 완성 MP4의 첫 훅·중간 제품 설명·마지막 CTA를 화면과 소리로 확인한다. 실제로 들을 수 없다면 음성 품질은 `unverified`로 기록하고 고객에게 청취를 요청한다. ffprobe, 파형 또는 무음 검사만으로 음성·창작 품질 합격을 주장하지 않는다.
9. 문제 구간만 수정하고 재사용 가능한 영상·음원은 재생성하지 않는다. `review_save`를 정직하게 작성하고 승인된 버전만 `project_publish`한다. Studio 재진입·원본과 음원 복원·최종 다운로드를 확인한다.
10. 고객에게 결과 링크, 남은 수정점, 생성/렌더 비용과 재생성 횟수를 전달한다. HIOB에 저장하는 자료만 동기화하며 다른 폴더, 계정 인증 파일, Codex 대화는 업로드하지 않는다.

MCP 0.5.0 기준 / 스킬 1.0.0. 제공자 모델·가격·스키마는 실행 시 현재 응답으로 확인한다. 도파민·조회수·광고 성과나 동일 창작 품질을 확률로 보장하지 않는다.
