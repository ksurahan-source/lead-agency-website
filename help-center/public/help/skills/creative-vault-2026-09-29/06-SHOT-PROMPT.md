# 이미지 설계와 움직임 프롬프트 분리

사용 시점: 모델에 기획 전체를 넣어 엉뚱한 영상이 나올 때

## 이미지부터 완성한다
한 프레임에 인물·제품·배경·구도·빛·행동 시작 상태가 있어야 한다. 인물카드와 소품카드는 참조 자료이고 실제 생성 입력은 이를 반영한 장면 이미지다. HIOB 현행 H3·Seedance 연결의 참조 입력은 한 장이며 외부 음성 입력은 없다.

## 움직임 프롬프트
“인물이 제품을 집어 가슴 앞에 든다. 제품으로 시선이 이동하고 고개를 짧게 끄덕인다. 카메라는 고정된 상반신 구도. 끝에서 손과 제품을 안정적으로 유지한다.”
한 원본에 한 주된 행동·하나의 카메라 움직임을 우선한다. 이것은 여러 편집 컷을 못 만든다는 뜻이 아니다. 기존 원본을 의미 있는 구간으로 나눠 사용한다.

## AI 프롬프트
이미지용 [인물·제품·장소·빛·구도·시작 상태]와 영상용 [주동작·반응·카메라·끝 상태]를 따로 써줘. 기본 단일 행동 원본에서는 나레이션 전체·CTA·음악·여러 장소 전환을 동작 프롬프트에 섞지 마. 아래 멀티샷 실험에서는 각 구간의 행동·구도·컷 전환을 명시해 별도로 설계한다. 모델 가이드에서 현재 입력·길이·활성화 여부를 확인하고 실제 견적을 따른다.

## 통과 기준
원본에 필요한 행동이 실제로 있다. 기획상 “펜을 놓는다”인데 이미 놓인 펜만 비추면 미완료다. 외부 녹음/Typecast를 얹는 것이 입모양을 재생성한다고 주장하지 않는다.

관련: [의미 묶음](01-BEAT-GROUPS.md), [편집 연결](09-ASSEMBLY.md).

## Seedance 전용 멀티샷: 15초 원본에 3초 안팎의 다섯 컷 담기

2026-09-30 사용자 확정: HIOB에서 이 멀티샷 묶음 생성 방법은 Seedance 2.5 전용이다. H3 및 다른 모델에는 사용하지 않는다. 다른 모델을 선택했으면 컷별 개별 원본 생성·편집으로 설계한다. 이것은 HIOB의 사용·지원 규칙이며 다른 제공사 전체의 기술적 불가능을 주장하는 문장이 아니다. 정확히 다섯 컷·각 3초 전환과 자동 분할은 실제 결과 검수가 필요하다. 문서 저장은 새 유료 실험의 승인이 아니다.

### 원본과 컷을 구분한다
하나의 15초 생성 원본 안에 여러 장면을 순서대로 담고 편집에서 필요한 구간을 쓴다. 원본 안의 장면은 순차적이다. 서로 다른 원본 묶음은 기존 제공사 한도 안에서 병렬 처리할 수 있다. 다섯 컷이 원본 생성 요청 다섯 개를 뜻하지 않는다. 3초는 목표 편집 길이이며 현행 HIOB 원본 입력의 최소 5초와 구분한다.

같은 인물·제품·장소·조명과 하나의 상황을 공유하는 컷부터 묶는다. 무관한 다섯 장소, 복잡한 제품 사용, 입모양과 대사 시각이 중요한 장면은 별도 원본으로 분리할 수 있다. 길게 생성한다고 자동으로 자연스럽게 연결되는 것은 아니다.

### 15초 묶음의 설계 예시
- 목표 0–3초: 주인공이 문제를 발견하는 표정.
- 목표 3–6초: 문제를 보여주는 손·소품 클로즈업.
- 목표 6–9초: 해결 방법을 시도하는 행동.
- 목표 9–12초: 자료로 뒷받침되는 행동 결과. 제품 효과를 창작하지 않는다.
- 목표 12–15초: 납득하는 반응과 다음 구간으로 연결.

이 시간은 모델에 주는 연출 목표다. 생성된 원본에서 실제 장면 전환 시각을 확인한 뒤 source in/out을 정한다. 무조건 3초마다 잘라 동작·발화·제품 설명을 끊지 않는다. 다섯 장면은 예시이며 장면 밀도가 과하면 2–3장면으로 줄인다. 나레이션은 컷을 넘어 이어지고, 정확한 박자·제목·자막·효과음은 편집에서 맞춘다. 외부 음성을 덧씌워 입모양까지 맞는다고 가정하지 않는다.

### AI에게 줄 기획 프롬프트
“선택 모델이 Seedance 2.5일 때만 아래 멀티샷 방법을 적용해. H3 등 다른 모델이면 묶음 생성을 요청하지 말고 컷별 개별 원본을 설계해. 편집 컷 수와 유료 생성 원본 수를 분리해줘. 같은 인물·제품·장소를 공유하는 컷을 10–15초 원본 묶음 후보로 구성해. 각 묶음에 [원본 ID | 총 길이 | 유지할 인물·제품·조명 | 하위 컷 ID | 목표 시간 | 행동·구도 | 전환 방식 | 실패 시 별도 보충할 컷]을 적어줘. 15초 안에 다섯 컷을 넣는 안과 2–3컷을 넣는 안의 복잡도를 비교해. 현재 모델 가이드와 실제 도구 스키마를 확인하고, 없는 multi_shot 필드를 보내지 마. 목표 시각을 실제 검수 시각으로 기록하지 마. 유료 실행은 기존 유효한 권한과 견적 범위에서만 진행해.”

### Seedance 전용 영상 프롬프트 예시
“15초 광고용 멀티샷 시퀀스. 같은 성인 인물, 같은 소품, 같은 방과 조명을 유지한다. 목표 0–3초: 중경에서 문제를 알아차린다. 하드 컷. 목표 3–6초: 손과 문제의 근접 화면. 하드 컷. 목표 6–9초: 해결 행동을 보여준다. 하드 컷. 목표 9–12초: 실제 자료로 확인 가능한 결과를 보여준다. 하드 컷. 목표 12–15초: 주인공의 짧은 납득 반응. 장면 사이 얼굴·소품을 변형하는 모핑을 피한다. 화면 내 읽을 수 있는 글자·로고·자막은 생성하지 않는다. 대사·음악은 별도 편집한다.”

이는 검증 전 출발 프롬프트다. 실제 제품 자료에 없는 해결 효과나 고객 경험을 넣지 않는다. 모델이 네이티브 소리를 만들 수 있으므로 음성 없음이라는 지시만 믿지 말고 기존 원본 오디오 정책을 따른다.

### 모델 선택 규칙과 현재 HIOB의 경계
- Seedance 2.5: 멀티샷 묶음 생성에 사용하는 모델이다. PiAPI가 지원하는 15초 생성 안에 순차 장면을 프롬프트로 설계한다. 현행 HIOB는 원본 5–15초와 단일 참조 이미지를 연결하므로, 제공사에 있다는 이유로 여러 참조 이미지나 없는 도구 필드를 임의로 사용하지 않는다.
- MiniMax H3 및 다른 모델: HIOB에서는 이 묶음 생성 방법을 사용하지 않는다. 필요한 컷의 개별 원본을 생성하고 편집에서 이어 붙인다. Seedance 프롬프트를 그대로 보내거나 자동으로 다른 모델에 대체 실행하지 않는다.
- 정확히 3초씩 다섯 컷이 나온다는 보장은 확인하지 않았다. Seedance에서도 생성 후 실제 전환 시각과 행동을 검수하고 편집에서 맞춘다.
- 확인일 2026-09-30. 제작 전 현재 활성 모델·실제 스키마·견적을 확인한다. 새 모델 지원은 명시적인 HIOB 지원 변경·검증 전까지 추가하지 않는다.

### 비용 비교와 재생성
같은 Seedance 모델에서 3초 편집 컷 12개를 현재 최소 5초 원본으로 각각 만들면 최소 60초·12회 생성이다. 15초＋15초＋6초로 묶어 모두 사용할 수 있다면 36초·3회다. 같은 초당 단가·해상도이고 참조 입력 추가요금·실패·재생성 비용이 없다는 가정에서 생성 분량은 40% 줄어든다. 이는 산술 예시이며 실제 절감액·품질·대기시간의 측정 결과가 아니다. 실제 비용은 서버 견적을 따른다. 묶음이 복잡해 재생성을 반복하면 절감 효과가 사라질 수 있다.

좋은 구간은 유지하고 실패한 컷만 독립 원본으로 보충해 편집한다. 이는 원본 파일 안의 특정 장면만 제공사에서 공짜로 재생성한다는 뜻이 아니다. 새 생성에는 새 견적과 기존 유효 예산 확인이 필요하다.

### 검수와 채택 기준
1. Seedance에서 동일한 내용의 개별 생성과 묶음 생성 실험안을 준비한다. 다른 모델에는 묶음 실험을 적용하지 않는다. 과금 전에 필요한 원본·길이·해상도를 견적에서 확인한다.
2. 생성 후 generation_inspect로 실제 프레임을 보고, 의심 구간만 motion 검사한다. 원본을 검수 때문에 전부 로컬 다운로드·반복 분할하지 않는다.
3. 채택 후보는 전체 motion/material_inspect로 필요한 행동·인물/제품 일관성·전환을 확인한다. 정지 이미지나 부분 구간만으로 전체 합격을 기록하지 않는다.
4. 실제 경계를 타임코드로 기록하고 편집 컷의 원본 ID·in/out에 연결한다. 자동 경계 감지와 하위 컷별 자동 판정은 아직 구현·검증된 기능이라고 말하지 않는다.
5. 쓸 수 있는 컷 수, 원본 생성 비용, 전체 대기·검수·수정 시간, 재생성 횟수로 비교한다. API 호출 수 감소만으로 성공 처리하지 않는다.
