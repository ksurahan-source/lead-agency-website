# YouTube·Reels·AI 영상 기획 리서치

조사일: 2026-10-02. 전용 Exa/Firecrawl이 연결되지 않아 웹 검색과 공식 문서 원문을 사용했다. 플랫폼 추천/시청 경험, 광고 목적별 기획, 이미지·영상 프롬프트, 반복 검토, 실제 연결 모델 계약을 조사했다. 아래 18개 1차 자료를 근거로 제작 절차를 종합했다. 실제 최신 릴스/유튜브 영상을 시청한 표본 조사는 아니다. 기획마다 타깃·언어·업종에 맞는 최근 영상의 실제 관찰이 별도로 필요하다.

## 확인한 사실

- YouTube Shorts는 시청을 선택한 비율·평균 시청 시간·평균 시청 비율과 만족 반응을 추천에 활용한다. 특정 형식의 우대를 공개한 공식이 아니며 주제 관심·경쟁·계절도 영향을 준다. [Shorts 추천](https://support.google.com/youtube/answer/11914225?hl=en)
- 추천은 개인화되어 여러 사용자 행동·만족 신호를 조합한다. 조회수·좋아요만으로 다음 영상의 노출을 확정할 수 없다. [YouTube 추천](https://support.google.com/youtube/answer/16089387?hl=en)
- 제목·썸네일은 정확한 기대를 형성해야 한다. 최신 계정의 시청자가 보는 콘텐츠도 아이디어 자료다. [제목·썸네일](https://support.google.com/youtube/answer/12340300?hl=en)
- 유지율의 이탈과 스파이크를 장면으로 해석한다. 다시 보는 구간은 재미 또는 이해 어려움일 수 있다. [유지율](https://support.google.com/youtube/answer/9314415?hl=en)
- 현재 제목·썸네일 A/B 시험은 일반 영상에 최대3개를 비교하며 시청 시간을 기준으로 판단한다. Shorts에 같은 기능을 적용한다고 쓰지 않는다. [현재 A/B 도움말](https://support.google.com/youtube/answer/16391400?hl=en)
- Shorts 첫 순간과 미니 스토리를 강조한 2025-01-28 공식 창작자 인터뷰의 ‘1초 훅’은 해당 창작자의 조언이며 보편적인 알고리즘 통과 조건이 아니다. [Shorts deep dive](https://blog.youtube/creator-and-artist-stories/youtube-shorts-deep-dive/)
- Meta는 공유 가능성을 포함해 여러 예측을 조합한다고 설명했다. 단일 신호의 비밀 가중치를 만들지 않는다. 2023-06-29 발표는 현재 고정 가중치표가 아니다. [Meta 추천 설명](https://about.fb.com/news/2023/06/how-ai-ranks-content-on-facebook-and-instagram/)
- Instagram의 2024-05-02 원본 콘텐츠 추천 확대 설명은 당시 발표다. 추천 적격성·원본성을 확인하되 현재 모든 계정의 고정 배포 단계로 단정하지 않는다. [원본 콘텐츠 발표](https://about.fb.com/ltam/news/2024/05/ayudando-a-los-creadores-a-encontrar-nuevas-audiencias/)
- 전문 대시보드 Best Practices에는 제작·참여·도달 등 일반/계정별 조언이 있다. 실제 계정 접근 없이 계정별 권고를 안다고 주장하지 않는다. [2024-10-01 Best Practices](https://about.fb.com/news/2024/10/best-practices-education-hub-creators-instagram/)

## 정석 기획서 — HIOB의 운영 권고

1. 브리프: 누구에게/어디서/왜 보여주는가, 유기적 게시인지 광고인지, 메시지 한 가지, 시청 후 행동, 사실·제약·지원 분량.
2. 리서치: 공식 플랫폼 사실과 브랜드 원문, 실제 참고 영상의 관찰을 분리한다. 최근 예시3개가 없으면 research_pending과 접근 한계를 적고 계속 기획한다.
3. 주 모드 선택: 후기/UGC/병맛/게임/설명/드라마/비교 중 하나. 보여줄 사건과 시청 보상으로 선택 이유를 설명한다. 모드별 효율을 입증한 보편 수치가 있는 것처럼 쓰지 않는다.
4. 훅3안: 첫 화면·첫 대사·궁금증·회수할 보상을 세트로 작성한다. 실제 기획 이미지3장을 준비하고 한 방향을 골라 확장한다. 색만 바꾼 세 안은 약한 비교다.
5. 카드: 별도 인물 이미지(계정 버전 재사용), 소품의 상태/재질/접촉, 배경의 공간/광원/동선을 장면별로 연결한다.
6. 스토리보드: 타임코드, 장면 목적, 시작 상태→행동 하나→끝 상태, 구도/카메라, 정확한 화면 대사와 별도 해설, 현장음·음악·SFX/음악스팅·VFX, 자료화면, 다음 장면 연결.
7. 초안 비평: 처음 보는 모바일 시청자의 이해·관심·신뢰·읽기/듣기 부담을 검토한다. 구체적 약점 두 개 이상을 실제 내용으로 고치고 수정본을 다시 본다.
8. 생성 입력: 선택 모델의 실제 promptGuidance/단일 참조/길이/화질/음성 방식과 대조한다. 모든 소재를 다시 만들지 말고 실패·변경 부분만 별도 승인 범위로 처리한다.
9. 실물 검토: 실제 이미지→생성 소재의 얼굴/손/제품/문자/동작/발화→최종 MP4/음원의 순서로 본다. 구조 검사·파일 해시는 창작 품질을 인증하지 않는다.
10. 학습: 한 가지 비교 가설·관찰 시점·표본/조건·다음 수정 변수. 바이럴과 매출, 유기적 도달과 광고 성과를 분리한다.

이 단계들은 고품질 제작의 운영 기준이다. 없는 이미지·카드·관찰·재검토는 missing/unverified로 알려주며 제작 진행을 차단하지 않는다. AI의 시청자 관점 검토는 agent_review이고 인간 확인 사실을 발명하지 않는다. 고객의 이미 선택한 방향·원문·수치·소재를 보존한다.

## 이미지 생성 fallback

호스트 Codex/Claude의 실제 이미지 도구 유무를 확인한다. 있는 도구와 고객의 승인 자산을 우선 활용한다. 없으면 HIOB `project_sync → image_generation_status → image_generation_quote → 승인 범위 확인 → image_generation_submit → status → download → project_view_image` 경로를 쓴다. 카드/기획 이미지가 없다는 이유로 자동 유료 접수하지 않는다.

Seedream5 Lite/Pro는 고정 단가의 단일 출력 PNG를, GPT Image2.5 Flare/Sunburst는 medium·n=1·명시 크기를 전달한다. 단일 참조의 정확한 해시를 사용한다. GPT 제공사 비용은 토큰 과금이며 HIOB 고정 제작 견적과 구분해 usage를 보존한다. pending 영수증과 완료 이미지를 구분하고 모르는 접수는 자동 재전송하지 않는다. [Seedream 공식 계약](https://app.piapi.ai/docs/seedream-api/seedream-5), [GPT 공식 계약](https://app.piapi.ai/docs/gpt-image/gpt-image-api), [GPT async 계약 안내](https://piapi.ai/blogs/gpt-image-2-5-api-first-call-editing)

GPT의 1024×1536은 2:3, 1536×1024는 3:2, 1024×1024는 1:1이다. 9:16 원본을 생성했다고 말하지 않는다. 9:16 최종 프레임은 중요한 얼굴·문자·제품이 잘리지 않도록 별도로 구도/크롭을 검토한다. Seedream은 9:16/16:9/1:1을 지원한다.

# HIOB 광고 카피·줄거리: 본능 설득과 상식 전복

조사일: 2026-10-04. 사용자 방향: 이상한마케팅의 사람 본능을 다루는 설득과 돌고래유괴단처럼 초반 또는 후반에 상식을 뒤집는 광고를 HIOB·MCP의 기본 광고 방향으로 적용한다.

웹 검색과 저자 공개 원문, 제작자 인터뷰, 광고주 공식 캠페인 설명을 교차 확인했다. Exa/Firecrawl은 연결되어 있지 않아 웹 도구로 조사했다. 아래는 공개 자료에서 배운 원리와 HIOB가 만든 운영 해석이다. 유료 강의 전문이나 비공개 프롬프트를 읽었다고 주장하지 않는다. 작품의 프레임·음성 전체를 재생 검수한 연구도 아니므로 정확한 초수·대사·CTA는 확인되지 않은 경우 쓰지 않는다. 오래된 대표작은 구조 연구이며 최근 플랫폼 트렌드 표본을 대신하지 않는다.

## 1. 이상한마케팅에서 직접 확인한 설득 구조

자청의 공개 체험판은 설득 대상의 원하는 결과를 찾고, 선택을 막는 의심을 하나씩 해결한 다음 행동을 요청하는 순서를 설명한다. 자사 홈페이지 사례에서는 사업 성과를 원하는 고객이 업체의 실체와 실행력을 의심한다는 분석 아래 직원 모습·자체 사업·실제 고객 인터뷰를 사용했다고 설명한다. 『역행자』 사례에서는 저자의 출발점·운영 사업·체계·실행 사례로 독자의 불신을 다루었다고 밝힌다. 이는 저자의 설계 설명이며 성과 인과관계를 독립 검증한 사실은 아니다. [저자 공개 원문](https://vod.pudufu.co.kr/home/pdf_preview/402/16155)

공식 교육 목차에는 고객 분석, 본능, 카피, 도입, CTA가 따로 있다. 공개 목차에서 ‘8가지 본능’ 강의는 확인했지만 그 여덟 항목의 전문은 확인하지 못했다. 임의 목록을 이상한마케팅의 공식 분류로 만들지 않는다. [공식 커리큘럼](https://lms.isanghanacademy.co.kr/course/5)

**HIOB 해석:** 기능을 나열하기 전에 고객이 원하는 변화와 잃기 싫은 것을 구체적 상황으로 적는다. ‘좋은 제품을 원함’이 아니라 언제 무엇을 못 하고 그 때문에 무엇을 잃는지 기록한다. 선택된 primaryPain 하나와 연결하되 감정·동기를 사실로 단정하지 않고 고객 원문과 추론을 나눈다. 반론은 기분 좋은 주장으로 덮지 않고 실제 자료·결과물·과정·가격·조건으로 답한다. 근거가 없는 반론은 미해결로 남기고 주장 수위를 줄인다.

## 2. 돌고래유괴단에서 확인한 방향

2024년 Google 인터뷰에서 이성헌 부대표는 기괴함을 목적이 아닌 수단으로 설명한다. 소비자가 광고를 건너뛸 수 있으므로 브랜드 접근을 바꾸고, 주어진 문제의 전제부터 의심하는 사고를 권한다. 진로 두꺼비와 iPhone ETA 사례도 전통적인 모델·기능 설명에서 벗어난 접근으로 설명한다. [Google 제작자 인터뷰](https://business.google.com/kr/think/future-of-marketing/meet-the-leaders-dolphiners-interview/)

2026년 캐논 인터뷰에서 신우석은 고정된 스토리텔링 공식을 부정하고 프로젝트의 목적·본질과 새로운 접근을 강조한다. 카메라 캠페인에서는 결과 사진만 아니라 촬영 행위의 감정도 이야기로 풀고자 했다고 말한다. 아래 유형과 검수표는 돌고래유괴단의 공식 비법이 아니라 HIOB의 분석이다. [캐논 공식 감독 인터뷰](https://kr.canon/magazine/detail/10160?area2List=null&listMainCate=&listSubCate=&photoVstAreaSeq=null&seqArr=CUR)

## 4. 앞으로 HIOB가 쓸 기획 절차 — 자체 운영 기준

1. 고객의 욕구: primaryPain과 연결된 실제 상황, 원하는 변화, 잃기 싫은 것, 고객 원문/출처, 추론 여부.
2. 구매 반론: 가장 큰 의심 1개와 보조 의심 최대 2개. 각각 확인 가능한 답·자료·조건 또는 미해결 표시.
3. 뒤집을 상식: 관객이 믿을 법한 업종·역할·관계·인과·광고 관행 한 문장. ‘놀랍다’ 같은 추상어로 대신하지 않는다.
4. 구조 비교: 초반 전복형과 후반 반전형을 각각 제안하고 하나를 추천한다. 본능 설득이 중심인 광고에도 처음이나 후반에 기대가 달라지는 지점을 설계한다. 이미 승인된 대본은 이 기준을 이유로 몰래 변경하지 않는다.
5. 제품 회수: 반전 때문에 제품의 차이·혜택을 이해하게 되는 이유를 한 문장으로 적는다. 제품을 빼도 똑같은 반전이면 연결을 고친다. 원작의 대사·등장인물·구체적 사건은 재사용하지 않고 새 상황을 쓴다.
6. 근거와 행동: 이야기의 해결이 확인된 제품 근거·제공 조건과 맞는지 대조하고, 마지막 CTA가 어디에서 무엇을 얻는 행동인지 적는다.
7. 승인 화자 구성: 기본은 한 나레이터지만 고객이 2인 대화를 선택하면 각 대사별 승인 배역을 유지한다. 훅→공감/사건→설명·차이→근거/반론 해소→CTA의 논리와 정확한 전문·타이밍을 보존한다.

### 두 구조의 작성 양식

**초반 전복형:** 익숙한 상황 한 조각 → 즉시 예상과 반대인 행동/역할 → 왜 그런지 궁금한 질문 → 제품의 차이가 그 사건을 설명 → 근거·조건 → CTA. 무슨 상황인지 모르는 소음·비명·기괴한 화면만으로 출발하지 않는다.

**후반 반전형:** 관객이 믿는 해석 → 그 해석으로 자연스럽게 보이는 사건과 복선 → 정체/원인/역할 공개 → 앞 장면이 다른 의미가 됨 → 제품 차이·근거 → CTA. 마지막에 새 정보만 던지는 깜짝 등장과 구분한다. 제품을 늦게 공개하는 경우에도 무엇에 대한 이야기인지 이해할 단서는 둔다.

### 카피 작성

타깃이 쓰는 구체적인 말을 쓴다. 첫 대사는 상황·긴장·궁금증을 함께 만든다. 짧은 화면 카피와 나레이터 전체 대본은 따로 설계한다. 허위 숫자, 가상 고객의 실제 후기, 확인되지 않은 비교 우위로 반박을 제거하지 않는다. 가격·혜택·효능은 브랜드 원문을 보존한다.

### 검수표

| 질문 | 기록할 근거 |
|---|---|
| 어떤 욕구를 건드리는가? | primaryPain·고객 원문·상황·가설 |
| 무슨 상식을 어디서 뒤집는가? | 기존 기대·전복 beat·첫 화면/대사 |
| 왜 다음 장면을 보는가? | 미해결 질문·복선·답이 나오는 beat |
| 공개 뒤 앞 장면이 재해석되는가? | 복선 before/after 설명 |
| 제품이 이야기의 해결에 필요한가? | 제품 제거 시 달라지는 원인·해결 |
| 구매 반론을 실제로 해소했는가? | 반론별 자료·조건·미해결 표시 |
| 무엇을 믿고 무엇을 하면 되는가? | 실제 근거·조건·명확한 CTA |
| 승인 화자 구성과 원문을 지켰는가? | 나레이터 전문·버전·실제 음성 대조 |

AI 검토는 실제 고객 승인·구매가 아니다. 각 항목은 pass/fail/unverified와 이유를 적고 자동 성과 점수·새 유료 실행 승인으로 쓰지 않는다.

## 5. 연구 결과를 적용해 보는 HIOB 자체 초안

다음은 타깃 확인과 제품 근거 대조 전의 카피/줄거리 연구 초안이다. 출시 카피나 고객이 승인한 대본이 아니다.

- 초반 전복형: ‘광고를 완성했는데, 대표님은 영상을 보지 않았습니다.’ 대표가 영상의 때깔보다 ‘고객이 왜 우리를 사야 하는지’를 먼저 묻는 사건으로 전개한다. 전복 대상은 완성 영상=설득 완성이라는 가정이다. 제품 회수 후보는 사람의 방향 선택과 AI 제작 연결이며 실제 지원 과정으로 증명해야 한다.
- 후반 반전형: 사람들이 같은 제품을 보며 서로 다른 이유로 돌아선다. 처음에는 영상 화질 문제로 해석하게 하지만, 뒤에서 각자의 가격·신뢰·적합성 질문에 답이 없었다는 사실을 공개한다. 전복 대상은 더 예쁜 광고면 선택받는다는 가정이다. HIOB가 실제로 제공하는 기획·수정·근거 연결을 확인한 부분만 설명한다.

두 안 모두 구매 반론과 제품 자료를 확보한 뒤 한 나레이터의 대본 전문으로 발전시킨다. HIOB가 자동으로 고객을 조사하거나 매출을 보장한다는 주장은 넣지 않는다.
