# 가로 16:9와 세로 9:16을 함께 제작하기

사용 시점: 가로 광고·서비스 설명·유튜브 본편, 또는 같은 광고의 두 화면비 납품

## 먼저 출력과 사용 화면을 확정한다
가로는 plan_save의 plan.aspectRatio="16:9", 편집 canvas={width:1920,height:1080}이다. 세로는 "9:16", canvas={width:1080,height:1920}이다. 현재 고정 AWS 계약은 30fps·최대90초다. 가로도 3–5초 의미 묶음과 9초 안의 훅 목표를 유지하며 실제 발화·제품 작동에 따라 조정한다. 가로라고 긴 establishing shot을 의무로 넣지 않는다. 인물 수를 채우려고 새 관계 서사를 만들지 않는다.

## 원본 화질과 최종 캔버스는 별개
H3는480p·768p·1080p, Seedance는480p·720p·1080p를 선택한다. 초안 기본 화질은H3 768p·Seedance720p다. 최종 고화질이 필요하면 storyboard_quote.resolution 또는 generation_quote.plan.resolution으로1080p의 새 견적을 확인한다. 1920×1080으로 렌더한다고 낮은 해상도 원본의 세부 묘사가 복원되지는 않는다. 변경 없는 대사·음악은 재생성하지 않는다.

## 가로의 구도 설계
- 얼굴만 가운데 크게 두기보다 인물·제품·행동이 한 화면에서 어떻게 연결되는지 먼저 정한다. 인물이 왼쪽, 제품이 오른쪽인 구도는 출발 예시이며 고정 규칙이 아니다.
- 와이드로 상황을 보여준 뒤 손·제품 근접·짧은 표정으로 필요한 정보에 접근한다. 컷마다 시선·손 이동·제품 방향을 이어준다.
- 나레이터는 화면 밖 가이드로 흐름을 잇는다. 조력자는 제품을 건네거나 한 번 반응하는 등 같은 사건을 돕는다.
- 생성 첫 이미지를 처음부터16:9로 구성한다. 인물카드의 얼굴·복장과 제품카드의 형태·라벨은 유지하고, 장면 이미지의 프레이밍을 새로 잡는다. 세로 원본을 늘리거나 무조건 center crop하지 않는다.
- 사이트 UI나 제품 글자는 검증 가능한 원본을 사용한다. 이미지·영상 모델이 글자와 인터페이스를 정확히 재현한다고 가정하지 않는다.

## 4초 묶음의 가로 예시
예상 대사 “방금 놓은 펜, 또 찾고 있죠?”에 맞춰 0–1.2초 책상과 찾는 손의 중경 → 1.2–2.4초 물건 뒤 펜 근접 → 2.4–3.2초 짧은 표정 → 3.2–4초 제품을 둘 자리로 손 이동을 설계한다. 나레이션은 컷을 넘어 이어진다. 실제 발화 전 편집 가설이며 원본에 동작이 없는 구간을 crop으로 만들어냈다고 하지 않는다.

## 제목·자막과 안전영역
가로에도 제목 top/middle, 발화 자막 lower/middle의 현재 지원 배치를 쓴다. 인물을 옆에 두는 구도와 자막을 임의 x/y로 옮기는 기능은 다르다. 지원하지 않는 좌우 분할 패널·자유 좌표·임의 CSS를 API에 넣지 않는다. 카드나 자료의 배치는 승인된 원본 이미지에 설계할 수 있으나 별도 편집 가능 오버레이 기능처럼 설명하지 않는다.
세로1080×1920 좌표를 가로1920×1080에 복사하지 않는다. 제목88px·자막72px 및 large1.15는 현재 편집 안내의 출발값이며 가로 전용 최적값으로 검증된 것은 아니다. 실제 edit_check의 박스 충돌·잘림과 지원 글자 크기를 확인한다. 긴 문장은 의미로 나누고 제품·얼굴·재생 UI를 가리지 않는다. 데스크톱과 휴대폰의 가로 재생 크기에서 각각 읽어본다.

## 가로 이미지 프롬프트
승인된 CHAR_01과 PROP_01 참조를 유지한1920×1080 가로 단일 장면. [공간]에서 인물은 [위치·시선], 제품은 [위치·크기]에 있고 [한 가지 행동의 시작 상태]를 보여준다. [제품과 손]이 가리지 않고 보이며 상단 제목과 하단 자막이 놓일 영역에는 중요한 정보를 피한다. [조명·카메라 거리·일관된 소품]을 유지한다. 새 인물·제품·효과를 추가하지 않는다. 이미지가 실제16:9인지 생성 후 확인한다.

## 가로 영상 프롬프트
승인된16:9 첫 프레임을 유지한다. [시작 상태]에서 [한 가지 동작]을 하고 [끝 상태]에서 마친다. 얼굴·손·제품 형태·라벨·배경의 연속성을 지킨다. [필요한 카메라 움직임]만 지정한다. 외부 나레이션 장면이면 보이는 인물에게 해당 나레이션을 말하거나 입모양을 맞추라고 요구하지 않는다. 모델·길이·오디오 지원은 현재 PiAPI 가이드와 실제 스키마로 확인한다.

## 두 버전의 재사용 순서
1. 같은 주장·대본·CTA를 기준으로 가로/세로 산출물을 별도 파일과 편집 기록으로 구분하고 원본을 덮어쓰지 않는다. 자동 두 버전 생성 API가 있다고 가정하지 않는다.
2. 문구·발화 시간이 같으면 녹음/Typecast·음악·효과음을 재사용한다. 변경 없는 음성을 재합성하지 않는다.
3. 영상은 화면비·피사체 위치·해상도·사용권·여백을 확인해 사용한다. 얼굴·제품이 잘리면 새 구도로 장면 이미지를 만들고 필요한 컷만 다시 생성한다. crop이나 화면 확장은 현재 지원 여부와 실제 미디어 검수 후 결정한다.
4. plan의 비율을 변경하면 기존 plan hash와 연결된 direction/audio/edit가 자동으로 유효하다고 보지 않는다. 파일은 재사용하되 새 plan에 연결·검증하고 각 버전별 sync·AWS 견적·render를 진행한다.
5. 두 출력은 별도 렌더 작업이므로 각각의 실제 견적과 기존 승인·잔액을 확인한다. 자료 읽기나 화면비 변경이 유료 실행 허용을 늘리지 않는다.

## AI 제작 요청
같은 광고의 세로9:16과 가로16:9를 기획해. 공통 메시지·제품 근거·발화는 유지하고 각3–5초 묶음의 구도·인물/제품 위치·자막 여백을 비율별로 써줘. [공통 원본 | 그대로 재사용할 음원 | 새 프레이밍이 필요한 장면 | 실제 지원 필드 | 각 출력의 검수 항목]을 나눠줘. 가로의plan.aspectRatio와edit.canvas를 일치시키고 두 결과의파일·버전·비용을 구분해. 전체를 재생성하거나 세로 원본을 억지로 늘리지 마.

## 통과 기준
가로 plan→shot.aspectRatio→editorBrief.canvas→edit.canvas→AWS snapshot의1920×1080이 일치한다. 실제 MP4 규격·소리·자막·인물/제품 잘림을 확인해야 가로 납품 성공이다. 기존 세로 기본값과 세로 검수가 유지된다. 계약 테스트만으로 실제 가로 광고의 품질 합격을 주장하지 않는다.

## 정사각형 1:1 제작

정사각형은 plan.aspectRatio="1:1", edit.canvas={width:1080,height:1080}으로 설정한다. storyboard_compile이 Square 1:1 장면 프롬프트와 같은 크기의 편집 지시를 전달한다. generation_quote의 shots[].aspectRatio도 "1:1"을 사용한다. 세로·가로·정사각형 모두 30fps·최대90초 최종 출력 계약을 유지한다.

정사각형 첫 프레임을 처음부터 구성하고 얼굴·손·제품·라벨과 제목·자막 여백을 검토한다. Seedance 2.5는 참조 이미지 비율이 요청보다 우선하므로 1:1 참조 이미지를 사용한다. 메시지와 승인된 정확한 나레이션은 보존하며 비율별 파일·버전·견적을 구분한다. 기존 승인 기획이나 편집을 자동 변경하지 않는다. 최종 MP4의 1080×1080 크기와 잘림·자막·발화를 확인하기 전 실영상 검증을 주장하지 않는다.
